### 참석 응답 배경 · 최신 사용자 수정

모서리 추가 교정: 일정 항목은 반경 8, 탭 바깥 배경은 12라 차이가 있었다. 사용자 지적에 따라 기본·참석 항목 모두 `Radius/12`로 맞춘다. 원본 두 상태에 같은 변수를 연결하고 화면별 덮어쓰기는 하지 않는다.

추가 사용자 지적에 따라 인원 문구를 좁은 가운데 열에 가둔 구조를 다시 교정한다. 이전의 320 너비 인원 두 줄은 사용자가 원한 결과가 아니므로 완료 기준에서 제외한다. 인원 줄은 배지 아래까지 포함하는 넓은 영역을 사용하고, 배지의 항목 중앙 정렬은 유지하는 것이 목표다. 최신 사용자는 화면 너비 390에서 월 글자 크기가 괜찮다고 확인했다. 이를 기존 20/28 유지로 해석했지만, 실제 편집 상태는 이미 18/24였다. 20/28 복원 클릭은 자동 승인 검토에서 최신 사용자 의도와 맞지 않는다는 이유로 거절되어 적용되지 않았다. 추가 변경 없이 현재 18/24와 실제 가로 가운데 정렬, 화면 너비 390을 유지한다. 사용자가 확인한 글자 크기를 임의로 다시 바꾸지 않는다. 인원 줄 구조는 기본 원본에 부분 적용됐으나, 여백 설정창을 여는 작업이 자동 승인 검토에서 거절되어 제목·시간 여백, 참석 원본의 동일 구조, 반경 12 통일과 최종 검증은 미완료다. 이 단락은 교정 중 기록이며 적용 완료를 뜻하지 않는다.

9월 30일 첫 `암장 미정 · 19:30` 항목을 `참석` 응답으로 바꾸고, 연한 보라색 배경을 적용한다. 색상은 **내가 참석으로 응답했다는 뜻**으로 사용하며, 실제 방문 출석을 의미하지 않는다. 배지 문구도 함께 표시해 색상만으로 상태를 구분하지 않는다. 총원 4명을 유지하도록 인원은 `참여 3명 · 불참 1명 · 미응답 0명`으로 변경한다. 기존 첫 항목인 피크 성수는 미응답·중립 배경을 유지한다. 이전의 ‘Highlight 의미 미정·모두 중립’은 당시 교정 이력이며, 이번 요청으로 참석 응답의 배경 의미가 정해졌다. 실제 적용·검증 결과는 최신 상태 기록을 따른다.

### 사용자 추가 교정 · 반영 및 크기 검증 완료

추가 정렬·간격 교정: 월 표시 원본 `148:236`의 실제 글자 정렬이 Left인 것을 확인하고 **Horizontal Align center**로 바꿨다. 글자 영역은 Fill이며 양쪽 화살표는 각각 16×16이다. 부모의 배치만 보고 글자 가운데 정렬을 완료로 판단하지 않는다.

목록 정보 영역은 padding 0/Hug를 유지하고 시간과 인원 사이 간격을 `Space/4`로 조정했다. 제목·시간 묶음의 gap은 0이며, 바깥 정보 묶음 gap이 0에서 4로 바뀌었다. 최신 항목 높이는 **390에서 80, 320에서 96**이다. 320의 인원 두 줄과 배지·화살표 중앙, 날짜 그룹 간32를 확인하고 390×844로 복원했다. [항목 확대 검수](../../figma/assets/v05-item-spacing-refined.png). 아래의 76/92 수치는 이 추가 교정 전의 기록이다.

첫 교정 이후 사용자 검토에서 확인된 차이를 공통 원본에서 수정했다. 루트가 최종 390·320 이미지를 직접 비교해 확인했고 390×844로 복원했다. 아래 항목은 이번 후속 교정의 기준과 결과다.

- 필터와 달력/목록 전환: 트랙의 안쪽 여백과 모서리 곡률을 시안에 맞춘다. 원본 이미지의 빈 트랙 색상은 약 `#EAEDF3`이며, 현재보다 분명한 회색으로 구분한다. 화면별 덮어쓰기가 아닌 공통 표면과 원본에서 조정한다.
- 월 표시: 시안의 글자는 거의 검정이다. 보조색 대신 `Color/Text/Primary`를 사용하고 좌우 화살표도 같은 기준으로 맞춘다.
- 일정 항목: 상태 배지 글자는 배지 안에서 가로·세로 가운데, 배지와 화살표는 인원 줄을 포함한 **항목 전체 높이의 가운데**에 둔다. 위쪽 요약 행만 기준으로 가운데 정렬하지 않는다.
- 이 교정 당시 첫 항목의 연한 보라색은 기능상의 강조 기준이 없어 모든 항목을 중립 배경으로 통일했다. 이후 최신 사용자 요청으로 참석 응답에만 연한 보라색을 사용하는 기준이 추가됐다. 첫 항목이나 내일이라는 이유만으로 강조하지 않는다.
- 날짜 묶음 사이에는 약 32의 여백을 두고, 같은 날의 항목 간격과 구분한다. 각 날짜 제목과 해당 항목들을 배치 그룹으로 묶어 관리한다. 390·320 너비에서 배지 중앙 정렬과 긴 인원 문구의 잘림을 다시 확인한다.

탭 원본 수정 확인: 필터는 350×36/선택면 높이 30, 보기 전환은 84×40/선택면 높이 34/아이콘 20이다. 두 트랙 모두 `#EAEDF3`, 안쪽 여백 3, 바깥 모서리 12, 선택면 모서리 10으로 맞췄다. `Space/3`·`Radius/10`을 추가해 원본에 연결했고 필터 선택면은 기본 테두리를 적용했다. [필터 확대 확인](../../figma/assets/v05-filter-refined.png) · [보기 전환 확대 확인](../../figma/assets/v05-view-refined.png). 월 원본은 `Color/Text/Primary`로 변경했다. 항목은 도장·세 줄 정보·상태 배지·화살표를 가로 자동 정렬로 구성하고 전체 높이의 가운데에 맞췄다. 390에서는 높이 76/인원 한 줄, 320에서는 높이 92/인원 두 줄로 표시되어 잘리지 않았다. 세 항목의 배경은 동일하며 날짜 묶음 `166:1204`의 간격은 `Space/32`에 연결했다. 기존 Highlight 원본은 보존했지만 V05에서는 사용하지 않는다.

- 기존 시안과 비교해 상단 회원 수, 큰 제목, 필터 트랙, 굵은 월 표시와 좌우 이동, 달력/목록 토글, 날짜별 세 일정과 하단 메뉴를 교정했다. 루트가 부품별 이미지와 최종 390·320 이미지를 직접 검수했다.
- 작은 원본을 먼저 만든 뒤 연결된 인스턴스로 조립했다. PEAK·GRIP·미정 도장과 필요한 아이콘은 사용자 지시에 따라 직접 SVG로 제작했다. 기존 스타일을 전부 바꾸지 않고 Display 40/48, SectionSmall 18/24, CaptionSmall 12/16을 추가했다. 글꼴은 Noto Sans KR이다.
- 390×844와 너비 320에서 글자·도장·배지·하단 메뉴가 잘리지 않는 것을 확인했다. 이 예시는 별도 스크롤 없이 보이며 Figma 화면은 390×844로 복원했다. 기존 이미지의 `시간 미정`은 최신 명세에 맞춰 19:30으로 표시한다.
- 이번 완료 범위는 **V05 시각 교정과 기본 크기 적응 확인**이다. 새 필터·월 이동·보기·일정 항목·하단 메뉴의 화면 이동 연결은 하지 않았다. 새 부품의 숫자 변수 연결 전체 점검과 새 스타일·변수의 내부 ID 조회도 남아 있다. 디자인 시스템 전체 검증 완료와 구분한다.
- 실제 원본·세트·스타일·검증 목록은 [state.json](../../figma/state.json)의 `v05Correction`을 따른다. 다른 일정 화면은 이번 결과를 반영했다고 간주하지 않는다.

## 일정 작업 교정 기록 · 2026-09-30

사용자의 핵심 기준은 **기존 시안과 최대한 유사하게, 전체적인 디자인을 동일하게 유지하는 것**이다. Product Design 생성 이미지를 실제 Figma 컴포넌트로 옮기며 생기는 작은 픽셀 차이는 허용한다. 정보 누락이나 다른 형태의 부품으로 바꾸는 것은 허용되는 작은 차이가 아니다.

이번 작업은 시안의 구성 요소를 먼저 대조하지 않은 채 비슷한 기존 부품으로 화면을 조립하고, 디자인 일치보다 프레임 수를 진척으로 판단한 것이 문제였다. 원본에 연결된 인스턴스를 썼다는 사실만으로 올바른 재사용이라고 볼 수 없다. 서브 에이전트 결과를 검수하는 과정에서도 발견한 차이를 나중으로 미루어 다른 화면으로 확대했다. 직접 웹 조작의 어려움이나 초안이라는 명칭은 디자인 차이를 정당화하지 않는다.

재개 시 V05를 기준 화면으로 먼저 바로잡는다. 다음 항목은 사용자 지적에 따른 **재검증 항목이며 해결 완료 목록이 아니다.**

- 우측 상단 크루 회원 수와 크루 선택 영역의 배치
- 기존 하단 내비게이션의 아이콘·글자·간격·선택 상태
- 재사용 가능한 아이콘·도장 원본과 시안에 맞는 모양
- 일정 목록 항목의 구조, 정보 순서와 스타일
- 날짜·월 이동 컨트롤
- `전체 / 내가 참여한 일정` 필터 탭
- `달력 보기 / 목록 보기` 전환 탭

재개 순서: **기존 V05 이미지와 최신 확정 설명 대조 → 작은 원본 부품 준비 → 공통 묶음 조립 → V05 시각 비교 → 큰 차이 수정 → 나머지 일정 화면에 적용**. 픽셀 오차보다 전체 구성·정보 배치·부품 모양을 우선 확인한다. 자세한 공통 기준은 [디자인 시스템 규칙 2절](../../figma-design-system.md#2-만드는-순서)을 따른다. 현재 생성된 노드와 이미지는 작업 이력이며 승인된 디자인 기준으로 사용하지 않는다.

### V05 교정 재개 · 시안 대조표

사용자의 `v05 진행` 지시로 **V05만** 교정한다. 비교 기준은 [기존 V05 이미지](../../assets/screens/10-schedule-list-v3.png)와 화면 설계 2.4절이다. Astra가 웹 UI를 조작하고 루트가 이미지와 구조를 검수한다. 아래 표는 제작·검증 기준이며 완료 표시가 아니다.

아이콘·도장·상태 배지부터 준비하고, 필터·월 이동·보기 토글·목록 항목·상하단 영역을 공통 원본으로 조립한 뒤 화면에 사용한다. 그림 속 PEAK/GRIP은 예시 콘텐츠이며 로컬에 별도 공식 로고 파일은 확인되지 않았다. 로고 확보 여부와 적용 방식을 별도로 기록하고 임의 브랜드 원본으로 주장하지 않는다.

부품별 비교 기록:

- `Control/ScheduleFilter` 원본 `140:219`: 350×36의 회색 트랙에 두 FilterTab 인스턴스를 배치했다. [확인 이미지](../../figma/assets/v05-filter-component.png)에서 흰 선택 면·보라 글자와 기본 상태의 구조를 원본 시안과 비교했다. 구조와 화면 대비 비율을 확인했으며, 전체 V05 완료를 뜻하지 않는다.

## 확인 결과와 남은 점검

- 변수의 용도 지정과 코드 이름 연결을 읽어 확인했다. 잘못된 ALL_SCOPES 지정 0개, 코드 이름 누락 0개다. 웹 코드 이름은 향후 구현용 제안이며 실제 앱 코드에 연결됐다는 뜻은 아니다.
- 공통 기준, 작은 부품, 입력 부품, 공통 묶음의 이미지를 각각 확인했다. 버튼 9개, 입력칸 4개, 메뉴 행 2개의 상태가 분리되어 있다.
- 공통 묶음은 글자·아이콘·버튼의 인스턴스를 포함한다. 문구는 Text의 Content 속성, 아이콘은 교체 속성으로 관리한다.
- 입력 부품을 만들면서 텍스트 원본을 가변 너비에 맞게 바꿨다. 따라서 작은 부품 보드의 최종 배치 재확인은 남아 있다.
- 메뉴 행의 Icon 교체 속성은 세트의 기본값을 공유한다. **계정 삭제에 사용하는 인스턴스는 Icon을 휴지통 원본(7:67)으로 명시적으로 지정해야 한다.** 현재 원본 견본의 위험 행에는 기본 화살표가 보인다. 견본용 인스턴스도 올바른 아이콘으로 추가하고 검증한다.
- 390×844 기본 화면 및 320×690 작은 화면의 가변 너비를 확인했다. 인라인 미리보기에서 본문을 스크롤하면 계정 삭제 행 전체가 보이고 저장 버튼은 같은 위치에 유지됐다. 기준 화면은 390×844로 복원했다.
- 화면 배경은 Color/Surface/Default 변수에 연결했다. 화면의 보이는 요소 6개는 기존 인스턴스이며 연결 해제는 하지 않았다.
- 긴 문구, 새 배치 프레임의 숫자 변수 연결(현재 공통 값 0/20/24 사용), 전체 대비·연결·변수 감사와 사용자 검토는 남아 있다. 최종 검증 완료로 표시하지 않는다.
