# 전체 화면·명세 점검

점검일: 2026-10-02

**후속 반영 완료:** 아래 점검 당시 발견한 네 보완 항목은 사용자 지시에 따라 제작·명세 정리를 마쳤다. 현재 상태는 [브랜드·암장 폼·나가기 확인 검증](brand-gym-correction-2026-10-02.json)을 따른다. 아래 내용은 점검 당시 근거다.

새 독립 화면을 추가해야 할 뚜렷한 누락은 찾지 못했다. 다만 기존 웹 등록 폼의 진입점 두 곳, 작성 중 나가기 확인 부품, 문서의 오래된 설명은 보완해야 한다. 앞서 작업 목록이 비었다는 설명은 제작 목록 기준이었다. 이번에는 실제 기능의 진입점까지 대조해 아래 보완점을 찾았다.

## 확인한 범위

- 현재 Figma 모바일38개 기본 화면과 웹2개 기본 화면을 새로 PNG로 저장하고 확인했다.
- 모바일83개·웹3개 상태 시안의 번호·너비·목록과 화면 옆 기능 명세40개를 대조했다. 번호표 누락·미등록 시안·모바일390 너비 위반·모바일 명세 누락은 없었다.
- 로그인, 일정 작성·응답·취소, 개인 기록 작성·수정·삭제, 크루 방문·참석자·기존 기록 연결, 회원 기록·통계, 필터·기간 선택, 보관함·파일 보기, 프로필·계정 삭제, 크루 생성·가입·전환·탈퇴·관리자 이관, 관리자 웹 등록 경로를 기능 명세와 대조했다.
- 추가 다이얼로그도 확인했다. 개인 기록 연결 해제와 계정 삭제 전 관리자 이관 안내는 이미 있다. 다시 제작할 대상이 아니다.
- 기본 화면 사진은 모두 확인했지만83개 모바일 상태의 세부 정렬을 모두 새로 픽셀 단위 검수한 것은 아니다. 실제 프로그램의 저장·권한·알림·키보드 동작은 이번 정적 시안 점검으로 검증할 수 없다.

### 문서와 이름의 불일치

- 화면 설계서 첫머리는 승인된39개라고 적지만 현재 모바일 독립 화면은38개이고 웹은 별도2개다. 이전29개·64개 점검 결과가 현재 기준과 함께 앞부분에 남아 있다.
- 프로필 수정 설명에는 계정 삭제 확인창을 아직 만들지 않았다고 적혀 있다. 실제로05.02.02가 있고 작업 목록의 W02 참조는 더 이상 남은 작업을 가리키지 않는다. 크루 탈퇴의 W03·W04 참조도 같은 방식으로 정리해야 한다.
- 기능 명세2.1의 모든 조회 화면 로딩·오류 규칙은 개발 동작과 시안 제작 범위를 구분해 적어야 한다. 이 문장을 근거로 별도 로딩·실패 화면을 추가하면 사용자 확정 규칙과 어긋난다.
- 기능 명세2.3에는 작성 화면의 ‘크루 방문에 연결하면 해당 크루에 공개돼요’ 문구가 남아 있다. B03·S08-F 등에는 ‘내 기록 연결 안 됨’과 크루·월 안내를 표시하도록 한 과거 설명이 남아 있다. 최신 확정대로 반복 안내 문구를 없애고 작성·연결 동작만 유지해야 한다.
- 화면 설계02.12는 일정·크루 방문에서 변경 이력을 연다고 설명하지만 Figma 옆02.12 명세는 크루 기록만 설명한다. 일정의 변경 이력 설명을 같은 화면 명세에 포함해야 한다. 개인 기록 이력은 추가하지 않는다.
- 되돌리기 확인02.12.02 안의 배경 프레임499:47986 이름은 아직02.13.01이다. 겉 상태 번호는 맞지만 내부 이름을 정리해야 한다. 추가 화면이 발견된 것은 아니다.

## 추가하지 않을 것

- 가입 크루 없음은 일정 안의 상태로 문서에 유지한다. 별도01.06이나 미가입 전체 시안을 다시 만들지 않는다.
- 통계 기간의 최근 N일·월간·연간·전체는 이미 입력 영역 견본이 있다. 같은 바텀시트를 기간별 전체 화면으로 추가하지 않는다.
- 연결 해제 확인, 삭제·탈퇴·세팅 취소 확인, QR·초대 문제 안내는 이미 있는 공통 다이얼로그와 견본을 사용한다.
- 제공사 로그인·기기 권한·사진 선택은 기기와 제공사의 기본 절차다. 별도 앱 화면을 임의로 추가하지 않는다.
- 서비스 관리자용 별도 회원 관리·초대 재발급·운영 중 벽 추가·폐지·통합은 기존 후순위·범위 제외 정책을 유지한다.
- 더보기 메뉴의 실제 권한별 항목과 저장 후 이동은 개발에서 기능 명세대로 검증한다. 클릭 연결이 없는 정적 시안이라는 이유만으로 새 화면을 추가하지 않는다.
