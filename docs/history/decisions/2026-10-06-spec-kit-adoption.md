# Spec Kit 도입 · 2026-10-06

사용자는 GitHub Spec Kit과 Living Spec 방식을 선택하고 프로젝트 설정을 승인했다. 초기 앱·서버 개발의 명세·설계·작업·누락 확인 절차를 활용하고, 완료 후에도 명세를 유지하기 위해 선택했다. 현재 적용 규칙은 [개발 흐름](../../development-workflow.md)과 [프로젝트 원칙](../../../.specify/memory/constitution.md)에 있다.

공식 GitHub 릴리스 v1.1.0 소스를 프로젝트 내부 도구 환경에 설치하고 Codex 통합을 등록했다. 기존 자료는 로컬 Git 기준 커밋으로 보관했다. GitHub 원격 저장소는 만들거나 연결하지 않았다.

기능 전체를 새 문서로 복사하지 않고, 첫 [개발 기반 구성 스펙](../../../specs/001-development-foundation/spec.md)을 작성했다. 설정과 요구사항 품질 확인까지 수행했으며 앱 설계·구현·실기기 검증은 아직 하지 않았다.

설치 버전·관리 파일·현재 기능 선택 경로와 문서 연결 검사를 확인했다. 임시 사본에서 끊어진 스펙 링크, 없는 기능 경로, 프로젝트 밖 기능 경로를 넣어 검사 도구의 실패 감지도 확인했다. 자동검사 결과는 제품 동작 검증이 아니다.
