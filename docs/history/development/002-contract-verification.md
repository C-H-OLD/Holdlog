# 002 알림 계약·생성 소비 검사

2026-10-07 · [002 작업](../../../specs/002-shared-contracts/tasks.md) T003~T009 · [계약 대조](../../../specs/002-shared-contracts/contract-readiness.md).

## 확정과 범위

사용자는 개별 알림을 누르면 읽음 처리하고, 알림을 꺼도 목록에 쌓이는 것으로 확정했다. 제품 원본·미정 목록을 갱신하고 본인 수신 조회·단건/전체 읽음 계약2.1.0과 모델/멱등/새 수신 경계를 정의했다. 설정은 푸시 발송만 제한한다. 현재 가입 권한은 목록·읽음·대상 진입에서 별도 검사한다. 필드·처리 의미의 원본은 [C09](../../../packages/contracts/conventions.md#수신-목록과-읽음--c09)이며 여기에 사본을 두지 않는다.

## 요구사항과 후속 전달

FR-001은 같은 HTTP/Runtime·의미·원본 정책, FR-002는 수신 소유/읽음/발송 분리 모델, FR-003은 현재 권한·같은 키/읽음 TX·수신 경계, FR-004는 UTC/IANA·날짜/정렬·전역 미읽음 수, FR-005는 원본 예제와 세 앱 typed/값 소비, FR-006은 확정 답변/운동 시작 미정/외부 검사의 분리로 연결했다. [FR·SC 작업 대조](../../../specs/002-shared-contracts/contract-readiness.md#frsc와-작업-대조)와 같은 원본을 사용한다.

SC-001~003의 계약 형식/생성/예제 경계는 위 검사로 확인한다. schema 검사가 실제 권한·DB 변경·중복 생성0건을 증명하지 않는다. SC-004의 C번호/operationId/소비 기능/45화면 연결은 정적 대조했다. 담당자 미지정·에이전트 단독 검토를 사람 간 합의로 표시하지 않는다. T010의 최종 병합 기준 전달은 필수 PR 병합 후 수행한다.

017 FR-005~006·T82~T85는 실제 목록/날짜 그룹/단건 클릭·실패 되돌림·전체 목록/새 수신·재진입·다른 계정/탈퇴 접근·설정 꺼진 수신/푸시 분리·재요청/응답 유실·TX를 구현/검사한다.003은 현재 Route와 공통 UI 진입을 조립한다. 그 밖의 기능은 자기 C번호의 원본을 사용해 독립 구현하고 선행 기능과 실제 연동 후 완료 판단한다. 물리 서버·실제 휴대폰·전체 새 예제의 실제 Chrome/Hermes 실행·제품 컨트롤러/DB/UI는 미수행이다.
