# Holdlog Figma 디자인 시스템 규칙

현재 기준 · 2026-10-06: 모바일39개 독립 화면·86개 상태 시안·39개 화면 옆 명세, 관리자 웹2개 독립 화면·3개 상태 시안·2개 명세다. 현재 화면 목록은 [번호표](./screen-numbering.md)와 [현재 작업](./figma/README.md)을 따른다.

갱신일: 2026-10-06

## 1. 목적과 적용 범위

**작은 공통 부품을 먼저 만들고, 그 부품을 재사용해 모든 화면을 만든다.** 새 화면이 추가되어도 버튼·글자·입력칸·메뉴가 같은 규칙을 유지해야 한다. 원본 부품을 고치면 이를 사용하는 화면에도 함께 반영되도록 연결을 유지한다.

이 규칙은 앞으로 만드는 모든 Holdlog Figma 화면과 기존 화면 수정에 적용한다. 한 번만 나오는 요소도 재사용할 수 있는 구조로 만든다. 화면의 배치용 프레임은 사용할 수 있지만, 버튼·텍스트·아이콘 같은 사용자에게 보이는 요소를 화면 안에서 따로 그려 공통 규칙을 우회하지 않는다.

- 제작 범위는 [현재 번호표](./screen-numbering.md)를 따른다. 문서에만 있는 추가 화면을 임의 제작하지 않는다.
- **모바일 너비는390, 관리자 웹 너비는1440으로 고정한다. 긴 시안의 높이는 모든 내용이 보이도록 늘린다.** 모바일을320 등 다른 너비로 바꾸거나 별도 작은 화면 테스트를 하지 않는다. 실제 개발의 비율 조정은 구현 단계에서 다룬다.
- 대상 파일: [Holdlog Figma](https://www.figma.com/design/vla4pXPo8FaCWFXfpIbYzx/Holdlog)
- 공통 부품의 노드·사용 화면·검증 자료는 [현재 Figma 자료](./figma/README.md)와 [상태 자료](./figma/state.json)에서 찾는다.
- 공통 글꼴은 **Noto Sans KR**, 현재 Figma 작업 도구는 **figma-console MCP**다. 연결 파일·공통 원본을 확인한 뒤 편집하고 현재 PNG로 검수한다.
- 화면 내용: [화면 설계](./screen-design.md), 동작: [기능 명세](./functional-spec.md), 순서·검토 상태: [화면 작업 목록](./screen-worklist.md)을 따른다.
- 기존 참고 이미지와 설명이 다르면 최신 확정 설명을 따른다. 미확정 제안을 확정 디자인처럼 적용하지 않는다.

## 2. 만드는 순서

### 2.1 기존 시안의 디자인 유지 · 2026-09-30 사용자 확정

**기존 디자인과 최대한 유사하게 만들고, 전체적인 디자인을 동일하게 유지하는 것이 중요하다.** 현재 시안은 Product Design으로 직접 생성한 이미지다. 실제 Figma 컴포넌트와 자동 정렬로 옮기면서 작은 픽셀 차이가 생길 수 있다. 픽셀 단위 완전 일치는 목표가 아니며, 컴포넌트 재사용과 기존 디자인 유지라는 두 조건을 함께 충족해야 한다.

| 판단 대상 | 기준 |
|---|---|
| 허용되는 작은 차이 | 글꼴 렌더링, 정수 크기 맞춤, 자동 정렬과 공통 간격 적용 등에 따른 작은 위치·크기 차이. 전체적인 인상과 정보의 순서·비중은 유지한다 |
| 유지해야 하는 디자인 | 상단·본문·하단 구성, 정보 위치와 중요도, 화면의 여백과 밀도, 글자 크기의 관계, 색상과 선택 상태, 버튼·탭·목록 항목의 모양, 아이콘과 도장의 시각적 형태 |
| 단순 픽셀 차이가 아닌 문제 | 회원 수 누락, 다른 하단 아이콘 사용, 도장을 일반 위치 아이콘으로 일괄 대체, 목록 항목을 다른 카드로 변경, 월 이동·필터·보기 전환의 누락 또는 다른 형태로 변경 |

기존 시안 이미지를 직접 열어 확인한다. 설명만 읽고 새 레이아웃을 추측하지 않는다. 이미지와 최신 확정 설명이 충돌하면 해당 부분은 최신 설명을 따르고, 나머지 디자인은 유지한다. 공통 규격으로 맞추는 작업이 임의의 재설계가 되어서는 안 된다.

이미지 시안 생성은 Astra 모델의 서브에이전트가 맡는다. 생성 이미지를 Figma의 한 장짜리 이미지 화면으로 옮기지 않는다.

### 2.2 부품부터 조립

| 순서 | 만드는 것 | 예시 |
|---|---|---|
| 1 | 공통 값과 스타일 | 색상, 글꼴, 글자 크기, 간격, 모서리, 테두리, 그림자 |
| 2 | 최소 단위 컴포넌트 | 텍스트, 아이콘, 버튼, 입력칸, 아바타, 배지, 구분선, 도장, 날짜 칸 |
| 3 | 작은 부품을 조립한 공통 묶음 | 입력 항목, 메뉴 행, 방문 카드, 상단 영역, 하단 메뉴, 달력, 바텀시트 |
| 4 | 공통 묶음으로 조립한 화면 | 일정 달력, 기록 상세, 내 정보, 크루 정보 |

필요한 부품이 없으면 앞 단계로 돌아가 부품부터 추가한다. 미래의 모든 부품을 미리 만들 필요는 없지만, 현재 화면에 필요한 부품은 화면 조립 전에 준비해야 한다.

‘이미 있는 부품’이라는 이유만으로 모양이나 용도가 다른 부품을 대신 쓰지 않는다. 예를 들어 참여 응답 버튼을 필터 탭으로 쓰거나, 일반 카드를 시안과 다른 일정 목록 항목으로 쓰면 원본 연결이 유지되어도 올바른 재사용이 아니다. 적합한 상태나 공통 원본을 먼저 준비한다. 아이콘·도장도 원본을 먼저 만들고, 탭·월 이동·목록 항목·상하단 내비게이션은 그 작은 부품들을 조립한다. 필요한 실제 로고가 없으면 미확보로 기록하며, 대체 아이콘 상태를 원래 디자인 재현 완료로 보지 않는다.

**SVG 제작 지시(2026-09-30):** 시안과 모양이 다르거나 필요한 아이콘이 없으면 직접 SVG로 만든다. PEAK·GRIP 예시 도장도 사용자가 직접 SVG 제작을 요청했다. 이는 예시 콘텐츠를 재현하는 작업이며 공식 브랜드 로고 확보와 구분한다. SVG 파일을 렌더링해 시안과 비교한 뒤 작은 원본 컴포넌트로 등록한다. 전체 화면을 하나의 SVG로 대체하지 않는다. 01.02 제작 자료는 [SVG 목록](./figma/assets/v05-svg/manifest.json)을 따른다.

**도장 글자 규칙(2026-10-01 사용자 확정):** PEAK·GRIP처럼 읽을 수 있는 예시 도장 글자는 SVG 경로로 그리지 않고 Figma 텍스트를 쓴다. 공통 `Primitive/Text/PlaceStampLabel`의 인스턴스를 SVG 그림과 조립하고 `Content`로 문구, `Size=38/44/48/60`으로 도장 크기를 지정한다. 글자는 공통 Noto Sans KR Bold 스타일과 `Color/Text/OnAction`을 사용하므로 SVG 고유 그래픽 예외에 포함하지 않는다. 산·G 심볼과 원형 배경의 경로·그라데이션 예외만 남긴다. 향후 도장을 만들 때 [그림 전용 SVG](./figma/assets/stamp-text/manifest.json)를 사용하고 과거 SVG의 벡터 글자를 다시 가져오지 않는다.

### 2.3 화면 상태를 늘리지 않는 규칙 · 2026-10-02 사용자 확정

- 명세나 사용자 지시 없이 로딩·조회 실패·다시 시도·저장 중·저장 실패·권한 없음 상태를 임의로 만들지 않는다. 각각을 별도 전체 화면으로 복제하지 않는다.
- 먼저 기본 시안 안에서 필요한 상태가 이미 보이는지 확인한다. 한 화면에서 선택·미선택 등 모든 상태를 보여주고 있으면 **화면도 부품 견본도 추가로 만들지 않는다.** 기본 시안에 없는 상태만 필요할 때 변하는 부품을 옆에 표시한다. 상태가 있다는 이유만으로 각각을 반드시 제작하지 않는다.
- 같은 역할의 요소가 한 화면에 여러 개 있으면 **그 요소들에 서로 다른 상태를 나눠 표시하여 한 시안 안에서 확인한다.** 예:06.08.01에서 코드 버튼은 초록색 ‘복사됨’, 링크 버튼은 ‘복사’로 표시한다. 이미 화면 안에서 비교할 수 있는 상태의 별도 화면·부품 견본은 만들지 않는다.
- 한 화면 안에서 보여줄 수 없는 필요한 버튼·입력칸·선택 표시 상태만 보여줄 때는 기본 화면 옆에 **변하는 부품만** 공통 원본의 인스턴스로 배치한다. 부품 견본에는 별도 화면·상태 번호를 붙이지 않는다.
- 기본 화면에서 생긴 문제는 **그 화면 위 중앙 다이얼로그**로 처리한다. 다이얼로그는 **기존 화면 위에 배경을 어둡게 하고 겹쳐 표시한 대표 시안 1개**로 위치와 크기를 확인한다. 같은 기본 화면에서 여러 다이얼로그 메시지·버튼 상태가 필요하면 배경 화면을 반복 생성하지 않고 **추가 다이얼로그 부품만 대표 시안 옆에** 배치한다. 서로 다른 진입 화면의 대표 다이얼로그 시안은 각각 확인한다. 안내 문구를 본문에 따로 흩어 배치하지 않는다.
- 권한이 없으면 진입을 막는 화면에 권한 없음 화면을 추가하지 않는다. 저장 중 중복 누르기 차단은 동작으로 처리하며 별도 저장 중 시안을 만들지 않는다.
- QR 스캔은 계속 인식한다. 사용할 수 없는 QR은 다이얼로그로 알리고 닫으면 스캔을 계속한다. ‘다시 스캔’ 버튼은 두지 않는다.
- 초대 코드·링크 복사 완료는 **누른 버튼을 초록색 ‘복사됨’**으로 바꾼다. 토스트나 별도 복사 완료 화면을 만들지 않는다.
- 참조 이미지에만 있거나 제작자가 생각해 낸 안내·상태를 확정 내용처럼 추가하지 않는다. 실제 빈 목록처럼 내용이 달라지는 상태도 기존 확정 범위 안에서만 제작한다.

## 3. 공통 값과 스타일

반복 사용하는 디자인 값에 이름을 붙여 한곳에서 관리한다. 이를 디자인 토큰이라고 한다.

- 색상·간격·크기·모서리 등 Figma 변수가 지원하는 값은 변수로 관리하고 해당 속성에 연결한다.
- 글꼴·크기·굵기·줄 높이 조합은 텍스트 스타일로, 그림자는 효과 스타일로 관리한다. 지원되지 않는 속성은 원본 컴포넌트에서 통일한다.
- 색상은 `Color/Action/Primary`, `Color/Text/Primary`, `Color/Surface/Default`, `Color/Border/Default`, `Color/Status/Danger`처럼 용도로 이름을 붙인다.
- 간격과 모서리는 `Space/…`, `Radius/…`, 글자 스타일은 `Text/Title`, `Text/Body`, `Text/Caption`처럼 일관되게 관리한다.
- 문서의 보라색 #512AFF 계열, 보조색 #515B80 계열, 입력 배경 #F3F4F7 계열과 390 너비 기준은 출발점이다. 실제 채택 값은 Figma 변수·스타일과7절의 상태 자료에서 관리한다. 시안의 근사값을 확인 없이 확정값으로 기록하지 않는다.
- 암장 브랜드·지점 색상, 난이도 색상, 앱의 선택 색상은 의미가 다르므로 별도 항목으로 관리한다. 같은 보라색처럼 보여도 하나의 의미로 합치지 않는다.
- 01.02에서 연한 보라색 일정 항목 배경은 **내가 참석으로 응답한 상태**를 뜻한다(2026-09-30 사용자 수정). `참석` 글자 배지도 함께 표시한다. 실제 방문 출석·지점 색상·첫 항목·내일 표시와 구분하며, 미응답과 불참은 중립 배경을 사용한다. 공통 항목의 응답 상태 변형으로 관리한다.
- 01.03 날짜 시트는 2026-10-01 확정한 별도 표시를 따른다. 모든 항목은 흰색이며 시간 아래에 내 응답 줄을 둔다. 참석은 보라색 체크, 불참은 코랄색 ×, 미응답은 회색 빈 원과 문구로 구분한다. 한 번에 최대2개만 표시하고 목록 내부를 세로 스크롤한다. 01.02의 참석 배경 규칙과 혼동하지 않는다.
- 화면마다 임의의 색상·글자 크기·여백 값을 넣지 않는다. 새로운 값이 필요하면 먼저 공통 값에 추가하고 용도를 기록한다.

합계·공개 설정·미입력 등 오른쪽 안내는 오른쪽 끝에 정렬한다. 필수 입력은 공통 필수 배지를 사용하고 선택 입력에는 필수·선택 배지를 붙이지 않는다. 난이도 시안의 예시 순서는 흰색·노랑·주황·초록·파랑·빨강·핑크·보라·회색·갈색·검정의11색이며 실제 브랜드 항목 수를 제한하지 않는다.

## 4. 컴포넌트와 재사용 규칙

- 같은 역할의 부품은 원본 하나를 사용한다. `Schedule/Button`, `Record/Button`처럼 화면 이름만 다른 중복 원본을 만들지 않는다.
- 화면에는 원본과 연결된 **인스턴스**를 배치한다. 인스턴스를 일반 도형으로 풀어 연결을 끊는 `Detach instance`는 사용하지 않는다.
- 공통 묶음 내부에서도 작은 컴포넌트의 인스턴스를 사용한다. 비슷하게 다시 그린 도형으로 대체하지 않는다.
- 선택·기본·비활성·오류 등 상태와 필요한 크기는 같은 컴포넌트의 변형(Variant)으로 관리한다. 해당 부품에 필요한 상태만 만든다.
- 글자 내용은 텍스트 속성, 아이콘 교체는 인스턴스 교체 속성, 아이콘 표시 여부는 표시 속성처럼 수정할 수 있는 항목을 명시한다.
- 화면에서 바꿔도 되는 것은 문구·사진·숫자·선택 상태처럼 정의된 내용과 상태다. 색상·글꼴·간격·모서리를 화면별로 덮어쓰지 않는다.
- 사진·로고·지도·QR 같은 콘텐츠는 재사용 가능한 표시 컴포넌트에 넣는다. 콘텐츠 자체가 달라도 바깥 모양과 배치 규칙은 공유한다. 실제 브랜드 로고를 임의로 다시 칠하지 않는다.
- 내부 배치는 자동 정렬(Auto Layout)을 사용해 글자가 길어져도 간격을 유지한다. 화면의 최상위 배치 프레임에는 위치 좌표를 사용할 수 있다.
- 화면 전체 이미지를 붙여 놓는 것은 참고 자료이며, 편집 가능한 화면이나 컴포넌트 제작 완료로 보지 않는다.

권장 이름: `Primitive/Icon`, `Primitive/Text`, `Control/Button`, `Control/TextField`, `Data/Avatar`, `Data/Badge`, `Calendar/DayCell`, `Calendar/VisitStamp`, `Navigation/TopBar`, `Navigation/BottomTabs`, `Overlay/BottomSheet`. 기존 파일에 같은 역할의 원본이 있으면 먼저 재사용하고 이름만 다른 원본을 추가하지 않는다.

## 5. Figma 파일 구성과 매 작업 절차

기존 페이지와 부품을 먼저 확인한다. 이미 같은 역할의 공간이 있으면 그대로 사용하고, 없을 때 다음 구성을 만든다.

| 페이지 | 내용 |
|---|---|
| 00 Foundations | 공통 변수·스타일과 사용 설명 |
| 01 Components | 작은 원본 부품, 상태별 변형, 공통 묶음 |
| 02 Screens | 컴포넌트 인스턴스로 조립한 화면 |
| 03 References | 필요할 때만 기존 시안과 비교 자료 |

매 작업은 아래 순서를 따른다.

1. 이 문서와 대상 화면의 최신 설명·작업 상태를 읽고, 기존 시안 이미지를 직접 확인한다. 화면 영역별 요소와 그 모양·위치를 비교 목록으로 정리한다.
2. Figma의 현재 변수·스타일·컴포넌트와7절의 상태 자료를 확인한다. 문서와 파일이 다르면 실제 파일을 확인해 목록을 바로잡는다.
3. 필요한 요소를 ‘기존 부품 재사용 / 기존 부품에 상태 추가 / 새 공통 부품 필요’로 나눈다.
4. 필요한 공통 값과 작은 부품부터 만들거나 수정하고, 공통 묶음을 조립한다.
5. 원본 인스턴스로 요청받은 화면을 조립한다. 기본적으로 화면 하나씩 검토한다. 사용자가 여러 화면을 한 묶음으로 요청하면 해당 범위를 함께 제작하고, `02 Screens`의 이름 있는 Section 안에 개별 화면 프레임을 모은다.
6. 기존 시안과 Figma 화면을 비슷한 크기로 나란히 비교한다. 전체적인 인상, 정보 배치, 부품 모양과 누락부터 확인하고 작은 픽셀 차이는 과도하게 맞추지 않는다. 원본 연결 상태도 별도로 확인한다. 기준 화면의 큰 차이를 해결한 뒤 다른 화면으로 확대한다. 공통 원본을 바꿨다면 사용하는 기존 화면의 영향도 확인한다. 서브 에이전트의 결과에도 같은 검수를 적용한다.
7. 해당 부품·화면의 노드·사용처·검증 자료를 갱신하고, 작업 목록에 Figma 화면 링크와 검토 상태를 남긴다. 필요한 미리보기 이미지는 보조 자료로 저장한다.

공통 원본을 바꿀 때는 사용 화면을 먼저 파악한다. 같은 용도의 개선은 원본에 반영하고, 다른 용도의 모양은 의미가 있는 변형으로 추가한다. 기존 사용처가 있는 원본을 삭제하거나 대체할 때는 사용처를 먼저 옮기고 연결을 확인한다.

### README 관리 · 2026-10-01 사용자 확정

`docs/figma/README.md`는 현재 남은 작업을 중심으로 간결하게 유지한다. 완료한 작업은 남은 목록에서 제거하고, 상세 과정·노드 ID·검증 결과는 별도 기록에 보관해 링크한다. **Figma 클릭·화면 이동 연결은 필요하지 않으며, 남은 일이나 완료 조건에 포함하지 않는다.** SVG 그림의 선·점 위치를 공통 원본에서 관리하는 방식도 남은 작업으로 표시하지 않는다.

## 6. 완료 확인

### 6.1 화면 옆 텍스트 기능 명세

- 같은 화면의 상태 시안은 한 줄에 모으고, 마지막 시안 오른쪽64 간격에 **명세 하나만** 둔다. 현재 번호표의 화면 묶음에 적용한다. 상태마다 같은 설명을 반복하지 않는다.
- 실제 버튼·항목 이름을 제목으로 쓰고 그 아래 동작을 짧게 적는다. 달라지는 상태는 ‘상태 차이’로 함께 설명한다. 화면 위 번호 표시·표·카드 배경·테두리는 쓰지 않는다.
- 명세 폭420은 작업용 문서 규격이다. 앱 화면 너비390은 유지한다. 필요한 기존 부품 견본은 명세 오른쪽에 둔다. 명세는 앱 화면·추가 상태 수에 포함하지 않는다.
- 기존 Text/Section·Body·Caption 인스턴스와 Space20 변수를 재사용한다. 공통 원본 [Documentation/ScreenSpecification](https://www.figma.com/design/vla4pXPo8FaCWFXfpIbYzx/Holdlog?node-id=493-44481)은 [11 / Screen specifications](https://www.figma.com/design/vla4pXPo8FaCWFXfpIbYzx/Holdlog?node-id=493-44480)에 있다. Title·Details·Source의 Content로 편집한다. 원문은 `screen-design.md`·`functional-spec.md`이며 동작 변경 시 원문과 명세를 함께 갱신한다.

### 6.2 화면과 부품 검증

- 기존 시안과 전체적인 디자인이 유지된다. 필수 정보·컨트롤이 빠지지 않았고, 부품을 다른 모양으로 임의 대체하지 않았다. 허용한 작은 차이와 미해결된 큰 차이를 구분해 기록한다.
- 원본 연결 여부와 시각적 유사성은 각각 확인한다. 프레임 수, 컴포넌트 수, ‘초안’이라는 이름만으로 완료나 디자인 일치를 판단하지 않는다.
- 모든 화면 요소가 공통 컴포넌트를 재사용하며, 공통 묶음 내부의 작은 부품도 원본에 연결되어 있다.
- 텍스트·아이콘·콘텐츠 변경이 정해진 속성 안에서 이뤄지고, 임의의 디자인 덮어쓰기와 연결 해제가 없다.
- 색상·글자·간격·모서리 규칙이 변수·스타일·원본 컴포넌트로 통일되어 있다.
- 상태별 버튼·입력칸·메뉴가 같은 원본의 변형을 사용한다.
- 390 고정 화면에서 의도하지 않은 겹침과 잘림이 없다. 운동 중 기록 달력의 표시줄은 달력·도장과 겹침을 허용하며 화면 높이와 달력 크기를 유지한다. 다른 너비의 검증은 수행하지 않는다.
- Figma 구조 확인과 화면 이미지 확인을 모두 수행한다. 공통 부품 변경 시 기존 사용 화면도 확인한다.
- 노드 링크, 사용 화면, 검증 결과와 검토 상태가 문서에 남아 있다. 사용자 검토 대기와 제작 완료를 구분한다.
