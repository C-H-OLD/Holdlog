# 비공개 클라이밍 크루 일정·기록 앱 PRD

- 버전: 0.20
- 작성일: 2026-09-28
- 갱신일: 2026-10-06
- 상태: 최신 제작 화면과 사용자가 확정한 동작에 맞춘 제품 요구사항
- 기준: [현재 시안 목록](./screens.md)·[화면 번호표](./screen-numbering.md). 예전 문서에 맞추려고 최신 화면을 되돌리지 않는다. 화면에 보이지 않는 저장·권한 규칙은 최신 확정 기능 명세를 따른다.
- 제품 이름: Holdlog(가제)
- 제공 환경: iOS·Android 모바일 앱과 별도 서비스 관리자 웹.
- 운영 조건: 보유한 물리 서버에서 운영하며 외부 파일 저장소로 전환할 수 있어야 한다.
- 기술 선택·지도 설정·미디어 처리·저장소 운영은 [기술·운영 명세](./technical-spec.md)를 따른다.
- 계정: 구글·Apple 로그인 계정 자동 연결·병합 없음.

- 문서 목적: 첫 버전의 목적, 범위, 핵심 동작과 완료 기준을 정한다. 화면 설계와 기술 선택은 이후 기능 명세에서 구체화한다.

일정 응답은 참여·불참이며 초기 상태는 미응답이다. 일정 수정은 작성자·관리자만 가능하다. 입력·버튼·알림 동작은 [기능 명세 S04·S05](./functional-spec.md#s04-일정-생성수정)를 따른다.

## 1. 제품의 목적

초대받은 지인 크루가 운동 약속을 잡고, 실제로 함께 다녀온 사람과 운동 결과를 한곳에 남긴다. 혼자 또는 크루 밖에서 운동한 개인 방문도 기록한다. 방문할 암장을 고를 때는 참여자들의 공동·개인 방문 이력과 벽별 세팅 변경을 비교해 새로운 벽을 많이 경험할 수 있는 곳을 추천한다.

### 해결하려는 문제

- 운동 약속, 참여 신청, 방문 기록이 흩어져 있다.
- 전체 크루원과 실제 참석자가 달라 방문마다 참석자를 따로 관리해야 한다.
- 같은 방문을 각자 새로 만들지 않고, 공동 방문 기록 안에 개인 운동 기록을 모으고 싶다.
- 최근 방문일만으로는 새로운 문제가 얼마나 있는지 판단하기 어렵다. 암장은 여러 벽을 순서대로 세팅하기 때문이다.
- 공동 정보를 수정할 때 누가 언제 무엇을 바꿨는지 확인할 수 있어야 한다.

## 2. 사용자와 운영 범위

### 확정된 범위

- 첫 버전부터 한 계정이 여러 비공개 크루에 가입하고 크루를 전환할 수 있다.
- 모든 크루원은 소속 크루의 회원 목록을 보고, 회원을 선택해 공개된 개인 기록을 조회할 수 있다.
- 설치해서 사용하는 모바일 앱으로 만들며 iOS와 Android를 모두 지원한다.
- 구글·Apple 로그인 후 초대 코드 입력·QR 스캔·초대 링크로 크루 가입을 확인한다. 로그인만으로 비공개 크루에 접근할 수는 없다.
- 개인 기록의 방문 날짜·시간·지점·완등 개수·컨디션은 본인이 현재 가입한 모든 크루의 활성 회원에게 공개한다. 공개 미디어·후기는 기록이 연결된 크루에서만 조회한다. 공개 수치를 보여줄 크루를 따로 고르지 않으며 신규 가입 크루에서도 조회할 수 있는 기존 기록의 수치를 확인한다. 참석자 제외·공동 방문 삭제로 본인 전용이 된 기록은 기존 합의대로 비공개를 유지한다.
- 일반 크루원과 관리자는 크루별로 구분한다. A크루 관리자라고 B크루 관리 권한을 갖지 않는다.
- 앱 내 크루 생성·가입은 첫 버전에 포함한다. 생성자는 자동 가입하고 최초 관리자가 된다. 가입한 크루가 있으면 일정·기록 좌측 상단 ‘크루 이름 ⌄’에서 선택창을 열고, 크루 행을 눌러 바로 전환한다. 현재 크루만 체크하며 현재 탭을 유지한다. 내 정보의 내 크루 목록에서는 각 > 행을 눌러 크루 정보로 이동한다. 선택창과 목록 모두 생성·초대 가입 진입을 제공한다. 미가입 화면에는 상단 크루 진입을 숨긴다. 미가입 크루 검색·공개 탐색은 제공하지 않는다. 다른 크루 가입은 초대 코드·QR·초대 링크로만 진행한다.
- 방문 기록 작성자와 실제 참석자는 별개다. 불참한 크루원도 공동 방문 기록을 만들 수 있다.

### 운영 기준

- 로그인한 사용자가 앱에서 크루를 만들 수 있으며 초대 코드·QR·초대 링크 가입을 지원한다. 가입한 크루가 없을 때 일정 탭에는 ‘크루에 가입해보세요’와 생성·가입 진입을 제공한다.
- 일정·공동 방문·회원 목록·초대·알림은 해당 크루에 속한다. 개인 기록·개인 통계·보관함은 계정 전체 기준이다. 크루를 바꿔도 범위는 바뀌지 않는다(D08 확정).

- 초대 코드·QR·초대 링크는 크루에 미리 발급되어 있으며 무기한이다. 활성 크루원은 조회·공유할 수 있다. 회원 제외는 관리자 권한이며 재가입 차단도 적용한다. 초대 재발급은 현재 구현 범위에서 제외한다. 크루 생성자가 최초 관리자가 된다. 관리자 이관은 첫 버전에 제공하고 회원 제외·차단 해제 등 나머지 회원 관리 화면은 후순위다.

## 3. 첫 버전의 핵심 흐름

### 계획된 모임

1. 크루원이 날짜·시간을 정해 일정을 만든다. 암장은 나중에 정해도 된다.
2. 새 일정 푸시 알림을 받은 크루원들이 참여·불참을 선택한다.
3. 암장 선택·변경 화면에서 현재 참여자들의 방문 이력과 방문 예정일의 벽별 세팅 상태를 비교한 추천 목록을 보거나 암장을 검색한다.
4. 일정 작성자 또는 관리자가 암장을 정하거나 바꾼다. 모임 당일에도 변경할 수 있으며, 해당 일정의 참여 신청자들에게 푸시로 알린다.
5. 일정에 연결된 방문 기록이 생성되거나 일정 날짜가 지나면 종료 상태로 취급한다. 종료 버튼은 없으며, 날짜 경과만으로 실제 참석이나 방문 기록이 자동 생성되지는 않는다.
6. 크루원이 일정에 연결해 방문 기록을 만들고 실제 참석자를 확인한다. 운동한 당일에도 기록할 수 있다. 공동 메모와 사진·동영상을 남긴다.
7. 일정에 저장한 시간대의 당일 오후 9시까지 연결 방문 기록을 한 번도 생성하지 않았다면 기록 등록 요청 푸시를 보낸다. 각 참석자는 방문 기록 안에서 본인의 완등 개수와 개인 후기를 입력하고, 컨디션을 선택적으로 남긴다. 방문 기록이 있으면 개인별 입력이 덜 끝났어도 이 푸시는 보내지 않는다.
8. 개인 통계에서 기간을 선택해 방문, 운동 빈도, 완등 기록과 컨디션 변화를 확인한다.

일정은 날짜·시간을 필수로 입력해 모집한다. 암장을 먼저 정하고 참여자를 받는 방식도 지원한다. 참여자가 달라지면 암장 선택·변경 화면의 추천을 현재 참여자 기준으로 갱신한다. 기존 선택 암장은 자동 변경하지 않는다.

### 갑자기 모인 경우

1. 크루원 누구나 날짜·암장·실제 참석자를 선택해 방문 기록을 만든다.
2. 참석자들이 같은 방문 기록에 개인 운동 기록과 미디어를 추가한다.

### 혼자 또는 크루 밖에서 운동한 경우

1. 본인이 개인 방문을 만들고 날짜와 암장을 선택한다.
2. 본인의 완등 개수·후기·컨디션·사진·동영상을 남긴다.
3. 개인 통계와 이후 암장 추천에 공동 방문과 함께 반영한다. 개인 방문을 편집할 수 있는 사람은 본인이다.

## 4. 첫 버전 기능 요구사항

| 번호 | 기능 | 요구사항 |
|---|---|---|
| F01 | 비공개 접근 | 구글·Apple 로그인 후 크루를 생성해 자동 가입하거나 유효한 가입을 마친 활성 회원만 크루 정보에 접근한다. |
| F02 | 일정 생성 | 모든 크루원이 날짜·시간을 필수로 입력해 일정을 만들고 모집한다. 암장·설명은 선택 입력이다. |
| F03 | 일정 변경·취소·자동 종료 | 작성자와 관리자가 날짜·시간·암장·설명을 바꾸거나 일정을 취소한다. 당일에도 암장을 변경할 수 있다. 연결 방문 기록이 생성되거나 날짜가 지나면 종료로 취급하며 수동 종료 기능은 없다. |
| F04 | 참여 신청 | 회원은 참여·불참을 선택한다. 초기 상태는 미응답이다. |
| F05 | 실제 참석자 관리 | 방문마다 실제 참석자를 여러 명 선택한다. 신청자에서 추가·제외할 수 있다. |
| F06 | 공동 방문 기록 | 날짜·암장·실제 참석자·공동 메모를 저장하고 각 참석자의 개인 기록을 연결한다. 예정 일정과 연결하거나 독립적으로 생성한다. 개인 기록을 복사해 넣지 않는다. |
| F07 | 개인 운동 기록 | 사람별 색상·난이도별 완등 개수를 숫자로 입력한다. 반복 완등 포함 여부는 사용자에게 맡긴다. 컨디션은 5단계로 입력한다. 운동 중 개수를 바로 조절하고 종료 시 자동 저장하는 방식도 제공한다. 세부 동작은 [운동 명세](./workout-recording-spec.md)를 따른다. |
| F08 | 사진·동영상 | 방문 기록에 미디어를 추가하고 업로더를 보존한다. |
| F09 | 브랜드·지점·벽 정보 | 서버에 브랜드별 난이도 색상·단계를 등록하고 각 암장 지점을 브랜드에 연결한다. 벽은 지점별로 관리한다. 데이터 등록용 서비스 관리자 페이지는 첫 버전에 포함한다. |
| F10 | 벽별 세팅 | 운영자가 지점·벽별 날짜를 직접 등록한다. 탈거일과 세팅일은 같은 날로 취급한다. 세팅 당일 방문은 새 세팅을 경험한 것으로 본다. |
| F11 | 암장 추천 | 오늘 또는 미래 일정의 날짜, 참여자별 실제 방문 이력, 벽별 세팅을 비교해 추천한다. 과거 일정에서는 추천하지 않는다. |
| F12 | 기록 조회 | 달력·목록에서 날짜·암장·참석자별 방문 기록을 확인한다. |
| F13 | 변경 이력 | 일정·크루 방문의 변경 작업자, 시각, 대상과 변경 전후 내용을 남긴다. 개인 기록·개인 첨부 파일의 변경 이력과 과거 값은 저장하지 않는다. |
| F14 | 수정 되돌리기와 공동 기록 삭제 | 살아 있는 기록의 잘못된 수정을 권한에 맞게 되돌리는 기능과 삭제를 구분한다. 공동 방문 기록은 관리자만 삭제하며 삭제 후 복구할 수 없다. |
| F15 | 개인 통계 | 최근 90일·월간·연간·전체·직접 지정 기간으로 본인이 저장한 개인 기록의 방문 횟수, 방문 암장 수, 주당 운동 빈도, 완등 개수와 컨디션을 확인한다. 집계 기준은 15절과 기능 명세 D01·B03을 따른다. |
| F16 | 개인 방문과 연결 | 개인 기록이 기본 단위다. 혼자 다녀온 기록을 작성하거나 공동 방문 참석 시 생성·연결한다. 참석자 제외·공동 방문 삭제 시에도 본인 기록으로 보존하고, 재참석 시 참석자 제외로 끊긴 유효한 직전 연결만 재사용한다. 본인 직접 해제·탈퇴·삭제 후에는 자동 복원하지 않는다. |
| F17 | 암장 검색·선택 | 서버에 등록된 지점을 검색해 선택한다. 같은 화면에서 현재 참여자 기준 추천을 확인한다. |
| F18 | 푸시 알림 | 새 일정은 크루원 모두에게, 암장 지정·변경과 날짜·시간 변경·취소는 해당 일정 참여자에게 알린다. 일정 시간대의 당일 오후 9시까지 연결 방문 기록을 한 번도 생성하지 않았으면 일정 참여자에게 기록 요청을 보내며, 오후 9시 이후 만든 일정에는 이 요청을 보내지 않는다. 기록 부재 조건은 기록 요청에만 적용한다. |
| F19 | 크루 생성·가입·전환 | 앱에서 크루를 만들면 생성자가 최초 관리자가 된다. 다른 크루는 초대 코드·QR·링크로 가입하며 공개 탐색은 없다. 내 크루를 전환하고 각 크루의 데이터·권한을 구분한다. |
| F20 | 크루원 목록·개인 기록 조회 | 일반 크루원도 조회 중인 크루의 회원 목록을 보고, 회원을 선택해 조회 가능한 기록·통계와 기록 상세를 조회한다. 크루 정보에서 전달한 크루 ID를 유지한다. |
| F21 | 독립 암장 지도 | 하단 암장 메뉴에서 브랜드·지점·지역 검색, 지도 탐색, 지점 미리보기와 암장 상세를 제공한다. 일정 참여자·추천 순위와 독립적이며 지점 조회만으로 일정을 변경하지 않는다. |
| F22 | 앱 시작 공지 | 이미지 슬라이드 팝업·이미지별 링크·오늘 그만보기·닫기. 서비스 관리자 웹에서 관리하며 [기능 명세 S26](./functional-spec.md#s26-앱-시작-공지-팝업)을 따른다. |
| F23 | 오픈소스 안내 | 내 정보에서 앱에 사용한 오픈소스 안내 페이지로 이동한다. [기능 명세 S27](./functional-spec.md#s27-오픈소스-안내)을 따른다. |

## 5. 공동 정보와 개인 기록

소유권·연결·수정·삭제의 영향은 [기록 관계 설계](./record-relationships.md)를 따른다. 크루 방문 상세는 개인 기록과 접근 가능한 첨부 파일을 연결해서 보여주며, 표시와 소유권을 구분한다.

### 공동 방문 기록

일정·공동 방문·개인 방문은 모두 날짜·시간을 필수로 받는다. 실제 방문은 현재 또는 과거 시각만 저장하며 공동 방문은 실제 참석자 최소 1명이 필요하다. 입력한 시점은 UTC로 저장하며 입력 당시 시간대도 함께 보존한다. 화면은 기기 시간대로 변환해 표시한다. 일정 시간은 약속 시각, 방문 시간은 실제 방문 시각이며 종료 시각·운동 시간 길이는 필수로 추가하지 않는다.

- 방문 날짜·시간과 암장
- 실제 참석자 명단
- 공동 메모
- 연결된 예정 일정: 없을 수도 있음
- 연결된 개인 운동 기록과 사진·동영상

공동 방문 한 건에 여러 참석자의 개인 기록이 연결된다. 같은 날 서로 다른 암장을 방문했다면 별도 기록으로 만든다. 같은 날 같은 암장의 별개 모임도 가능하므로 날짜·암장만으로 자동 병합하지 않는다. 최초 연결은 아래의 후보 선택 방식으로 처리한다.

### 개인 운동 기록

- 기록 주인인 참석자
- 해당 방문 암장의 난이도별 완등 문제 개수
- 개인 후기
- 컨디션: 5단계, 선택 입력. 운동 전 상태인지 하루 전체 느낌인지 앱에서 강제하지 않고 사용자가 판단해 입력한다.

난이도의 색상·이름·단계 순서를 브랜드별로 정의하고, 방문 지점에 연결된 브랜드의 난이도를 사용한다. 관리자 웹의 브랜드 추가·수정 폼에서 이름·로고·난이도를 함께 저장한다. 난이도 항목은 추가·삭제하고 이름·색상을 바꿀 수 있으며11색은 시안 예시다. 암장 폼에서는 이미 등록된 브랜드를 선택하며 난이도를 별도로 저장하지 않는다. 변경해도 기존 기록의 브랜드 ID·난이도 키·완등 개수는 보존한다. 서로 다른 브랜드의 같은 색상을 같은 난이도로 취급하지 않는다. 같은 브랜드의 난이도별 개수는 지점별로 구분하거나 브랜드 기준으로 합산할 수 있지만, 지점마다 실제 체감 난이도가 같다고 단정하지 않는다.

첫 버전은 색상·난이도별 개수를 직접 입력한다. 같은 문제를 반복 완등했을 때 숫자에 포함할지는 사용자에게 맡긴다. 앱에서 문제를 식별해 중복을 제거하지 않으며, 통계는 사용자가 입력한 숫자를 합산한다.

### 개인 방문과 공동 방문의 구분

- 개인 기록은 본인의 독립 기록이며 크루 방문은 그 기록의 ID를 연결한다. 연결은 복사나 완등 개수 합산이 아니다.
- 크루 방문에는 실제 참석을 등록한다. 개인 기록의 작성·최초 연결은 본인이 크루 방문 상세에서 시작하며 빈 기록을 자동 생성하지 않는다.
- 연결은 같은 날짜·암장의 본인 기록만 허용한다. 연결 중 날짜·암장 변경 제한과 재연결은 [기능 명세 5.2절](./functional-spec.md#52-개인-기록-연결해제)을 따른다.
- 공동 방문 삭제·참석자 제외·연결 해제로 개인 기록과 본인 파일을 지우지 않는다. 본인이 개인 기록 자체를 삭제하는 경우와 구분한다.
- 개인 변경 이력은 저장하지 않으며 타인의 개인 내용은 수정할 수 없다.

소유권·공개 범위·삭제 영향과 연결 절차의 기준은 [기록 관계 명세](./record-relationships.md)에서 관리한다.

### 미디어

- 파일을 추가할 때는 로컬 미리보기만 표시하며 업로드하지 않는다. 개인 기록 저장 또는 크루 방문 등록·수정 저장을 누를 때 업로드한다. 작성 중 ‘업로드 완료’ 표시는 없다. 글·운동 수치를 먼저 저장하고 이후 파일별 업로드 진행·실패·재시도를 관리한다. 일부 파일이 실패해도 저장한 기록과 성공한 파일은 유지하며 실패한 파일만 다시 올린다. 지원하지 않는 파일도 해당 파일만 실패 처리한다(D05 확정).
- 새로 선택한 첨부에서 ×를 누르면 업로드 대상에서 빼며 해당 파일은 업로드하지 않는다. 기존 개인 첨부를 수정 중 ×로 제거하면 저장 성공 시 파일 자체와 해당 공유·썸네일·변환본을 삭제한다. 저장 전에는 기존 파일을 삭제하지 않으며 편집 취소·저장 실패 시 유지한다. 저장 성공 후 접근 차단과 삭제 작업 등록은 기록 변경과 함께 처리하고 실제 파일 삭제 실패는 재시도한다.
- 사진·영상 첨부는 기기에서 선택해 새로 업로드한다. 앱에 이미 올라간 파일을 불러와 다른 개인 기록이나 공동 방문에 다시 첨부하는 기능은 제공하지 않는다. 연결된 개인 기록의 첨부가 크루 방문 상세에 함께 보이는 것은 기존 기록을 조회하는 동작이며 파일 재사용 기능이 아니다.
- 파일 소유권과 공개·공유 관계를 구분하며, 공동 공유를 위해 원본을 별도 복제하지 않는다. 개인 기록 자체를 삭제할 때에는 기존 B02대로 본인 첨부 파일도 삭제한다.

- 새 개인 첨부는 기본 공개이며 파일별 비공개 선택이 가능하다. 비공개 파일은 본인만 조회한다. 표시 방식은 화면 설계를 따른다. 연결된 개인 기록의 공개 파일은 크루 방문 상세에서도 보여준다.
- 공개 파일을 비공개로 변경하면 타인의 원본·썸네일·공유 접근에서도 제외한다. 기존 비공개 파일과 분리된 본인 전용 기록을 기본 공개 정책으로 자동 재공개하지 않는다.

- 방문 기록, 업로더, 업로드 시각과 연결한다.
- 공동 방문에는 모든 크루원이 추가할 수 있고, 개인 방문에는 소유자만 추가할 수 있다.
- 일반 회원의 수정·삭제는 자신이 올린 파일에 한한다.
- 공동 방문 삭제 후 보존된 본인 파일은 내 정보의 사진·영상 보관함에서 다시 볼 수 있다. 불참자가 올린 파일을 보존하려고 가짜 방문 기록을 만들지 않는다.
- 첫 버전에는 제품 정책상 파일 용량·영상 길이·개수 제한을 두지 않는다. 지원 형식, 업로드 실패·재시도 처리는 기능 명세에서 정한다. 타인 미디어에 대한 관리자 특별 숨김·삭제 권한은 현재 제공하지 않는다.

| 일반적인 이력 수정·삭제 | 불가 | 일반 편집으로 불가 |

일정·크루 방문의 공동 정보 이력은 해당 내용을 조회할 수 있는 크루원이 본다. 개인 방문·운동 수치·컨디션·후기·첨부 파일의 변경 이력과 과거 값은 저장하지 않는다. 관리자에게도 개인 이력 조회 기능을 제공하지 않으며 공동 이력에 개인 내용을 넣지 않는다.

살아 있는 기록의 수정 내용을 되돌릴 때도 해당 정보의 수정 권한을 지켜야 한다. 공동 정보 되돌리기로 타인의 개인 기록을 덮어쓰지 않는다. 관리자가 삭제한 공동 방문 기록은 이력·휴지통·되돌리기 기능으로 복구하지 못한다.

크루 생성·가입과 관리자 이관은 첫 버전 모바일에 포함하고 나머지 회원 관리 화면은 후순위다. 암장·세팅 데이터는 [서비스 관리자 웹](./admin-spec.md)에서 등록한다.

### 탈퇴·제외·계정 삭제 — 확정

계정 삭제는 프로필 수정 내부에서 실행한다. 크루 정보의 탈퇴 행은 다른 메뉴와 높이·크기·정렬을 맞추며, 누르면 확인창을 연다. ‘개인 기록과 사진은 그대로 남아요’는 이 확인창에서만 안내한다.

자진 탈퇴는 해당 크루 접근을 차단하고 다른 크루 가입·개인 기록은 유지한다. 관리자 제외는 재가입도 차단하며 관리자 해제 전에는 유효 초대로도 재가입할 수 없다. 공동 방문·메모는 유지하고 나간 회원은 ‘탈퇴한 회원’으로 표시한다. 해당 크루의 개인 연결·개인 수치·본인 파일 공유는 해제하고 분리된 개인 기록은 본인 전용으로 보존한다. 재가입 시 관리자 권한과 본인 전용 공개 상태를 자동 복원하지 않는다.

계정 삭제는 모든 크루 접근 차단과 개인 기록·미디어·인증 정보 실제 제거를 포함한다. 다른 사람의 공동 기록은 유지하고 작성자 표시를 익명화한다. 관리자는 해당 크루의 다른 활성 회원에게 관리자 역할을 넘겨 본인이 일반 회원이 된 뒤에만 탈퇴할 수 있다. 관리자 역할이 남은 크루가 있으면 계정 삭제도 막고 해당 크루의 이관 화면으로 안내한다. 이관 대상이 없으면 다른 회원이 가입할 때까지 탈퇴·계정 삭제할 수 없다. 이관과 탈퇴는 별도 동작이다. 백업 운영 정책은 기능 개발 이후에 다룬다.

## 7. 참여 신청과 실제 참석

- 참여 신청은 앞으로 올 의사를 뜻한다.
- 실제 참석은 실제로 암장에 다녀왔다는 기록이다.
- 참여 신청은 미래 추천의 대상자를 정하는 데 사용한다. 신청만으로 이미 다녀온 방문 이력이 되지는 않는다.
- 신청했지만 불참한 사람은 실제 참석자에서 제외한다.
- 신청하지 않고 온 사람은 실제 참석자에 추가한다.
- 실제 참석한 날짜·암장으로 참여자의 방문 이력을 계산한다.
- 본인이 등록한 개인 방문도 실제 방문 이력으로 계산한다.
- 참석자 제외 시 기존 개인 기록을 본인에게만 보이는 개인 기록으로 보존한다. 같은 공동 방문에 다시 추가되면 참석자 제외 때문에 끊긴 직전 연결만 검증 후 재사용한다. 본인 직접 해제·탈퇴·삭제 후에는 자동 재연결하지 않는다.

## 8. 벽별 세팅을 이용한 암장 추천

### 추천의 의미

방문 예정일에 참여할 사람들을 대상으로, 각자의 마지막 방문 이후 새로 세팅된 벽이 많은 암장을 우선 추천한다. 최근에 갔던 암장이라도 그 이후 벽이 바뀌었다면 다시 추천할 수 있다.

추천은 실제로 시도하지 않은 문제를 판별하는 기능이 아니다. 첫 버전은 문제별 시도 이력을 수집하지 않으므로, 화면에는 ‘마지막 방문 이후 새로 세팅된 벽’이라고 표시한다.

### 필요한 정보

| 정보 | 내용 |
|---|---|
| 방문 예정일 | 추천 대상 날짜 |
| 추천 대상 참여자 | 해당 일정에 참여하는 사람들 |
| 암장별 벽 | 암장에 속한 벽 목록 |
| 세팅 이력 | 어느 날짜에 어떤 벽을 새로 세팅했는지 |
| 예정 세팅 | 방문 예정일까지 변경될 벽과 예정 날짜 |
| 실제 방문 이력 | 공동 방문의 실제 참석 이력과 본인이 등록한 개인 방문의 날짜·지점 |

### 확정된 원칙

1. 암장 전체가 아니라 벽 단위로 세팅을 관리한다.
2. 세팅 주기가 달라질 수 있으므로 고정 요일만으로 계산하지 않는다.
3. 참여자마다 마지막 방문일이 다르므로 사람별로 비교한다.
4. 마지막 방문 이후 바뀐 벽의 비율이 높은 암장을 우선 추천한다.
5. 방문 예정일까지 예정된 세팅도 고려하되, 완료된 세팅과 구분한다.
6. 방문 기록이 없으면 ‘방문한 적 없음’으로 단정하지 않고 ‘기록 없음’으로 표시한다.
7. 추천 이유를 사람이 이해할 수 있게 보여준다.
8. 암장 선택·변경 화면에서 현재 참여자 구성에 맞게 추천을 갱신한다. 참여자 수뿐 아니라 누가 참여하는지가 계산에 반영된다.
9. 추천과 별도로 등록된 암장을 검색하고 선택할 수 있다.
10. 과거 일정에는 추천을 제공하지 않는다. 오늘과 미래 일정에서만 추천을 사용한다.
11. 각 지점의 벽 목록과 벽 개수는 고정이다. 세팅은 기존 벽의 문제만 교체하는 작업이며, 벽의 추가·폐지·통합은 첫 버전에서 다루지 않는다.

### 첫 버전 계산 방식

참여 응답자의 마지막 실제 방문 이후 새로 세팅된 벽 비율을 계산하고, 계산 가능한 참여자들의 평균이 높은 암장을 추천한다. 방문 이력이나 세팅 정보가 부족하면 점수를 임의로 만들지 않는다. 시간대·동점·누락 정보 처리와 계산식은 [기능 명세 5.4절](./functional-spec.md#54-암장-추천-계산)을 따른다.

### 예시

A암장에는 벽 4개가 있고 매주 서로 다른 벽 하나를 완전히 세팅한다고 가정한다.

| 참여자 | 예정 방문일 기준 마지막 방문 이후 변경된 벽 | 새로운 벽 비율 |
|---|---|---|
| 민수 | 4개 | 100% |
| 지연 | 3개 | 75% |
| 수빈 | 2개 | 50% |

평균 비율 방식이면 A암장의 점수는 75%다. 사람별 표는 계산을 설명하는 예시다. 실제 추천 카드의 표시·정보 이동은 [암장 선택 화면](./screen-design.md#screen-03-02)을 따른다.

### 주의해야 할 경우

- 중간에 다시 방문한 사람은 그 방문일을 새로운 비교 기준으로 삼는다.
- 세팅이 취소·연기되면 변경된 일정으로 추천을 다시 계산한다.
- 탈거일과 세팅일은 같은 날짜로 사용한다. 세팅 당일 방문은 새 세팅을 경험한 것으로 취급하며 시각에 따른 선후 관계는 따로 입력받지 않는다.
- 세팅은 선택한 벽 전체의 문제를 교체하는 작업이다. 벽 일부만 교체하는 경우는 없으며 별도 교체 비율을 입력받지 않는다.
- 기록이 없는 개인 방문은 알 수 없으므로 추천은 앱에 저장된 이력을 기준으로 한다.
- 추천 결과가 변경되어도 확정된 모임의 암장을 자동으로 바꾸지 않는다.

## 9. 세팅 일정 관리

- 암장마다 벽 이름과 목록을 등록한다.
- 등록한 지점별 벽 목록은 고정으로 사용한다. 반복 세팅으로 바뀌는 것은 벽 자체가 아니라 해당 벽의 문제다.
- 세팅 한 건은 대상 지점·벽과 직접 등록한 날짜를 가진다. 새 세팅 예정일이 지나면 완료로 취급하고, 당일 방문도 해당 새 세팅을 경험한 것으로 계산한다.
- 첫 버전은 세팅 날짜를 직접 등록·수정·취소한다. 반복 주기를 이용한 세팅 자동 생성은 후순위다.
- 예정일이 지난 세팅은 실제 완료된 것처럼 표시하고 추천 계산에도 반영한다. 별도의 완료 확인이나 ‘확인 필요’ 절차를 두지 않는다. 이는 앱의 운영 규칙이며 외부 확인을 거쳤다는 의미는 아니다.
- 세팅이 연기·취소된 경우 원래 예정일을 수정하거나 취소해 추천에 반영한다.
- 운영자가 지점·벽별 세팅 관련 날짜를 직접 등록한다. 첫 버전은 공식 공지 자동 수집을 하지 않는다.
- ‘오늘 세팅 / 세팅 예정 / 완료’는 암장 지점 시간대의 오늘과 비교한다. 세팅 날짜 자체를 기기 시간대로 바꾸지 않는다.
- 지점·벽별 탈거일과 세팅일은 같은 날로 취급해 날짜 하나를 등록한다. 별도 이용 가능일 입력은 요구하지 않는다.
- 세팅 데이터의 입력·수정 범위는 [관리자 명세](./admin-spec.md)를 따른다.

## 10. 변경 이력과 데이터 보호

### 반드시 남길 내용

- 작업자
- 작업 시각
- 작업 종류: 일정·크루 방문의 생성, 수정, 삭제 및 허용된 수정 되돌리기
- 대상 일정·크루 방문·실제 참석·개인 기록 연결 관계
- 변경한 항목과 변경 전후 값
- 공동 파일 공유 변경은 필요한 식별 정보만 남기고 개인 파일의 변경 전후 내용은 남기지 않는다.

### 동작 원칙

- 이력 대상인 일정·크루 방문 변경은 해당 변경과 이력 저장이 함께 성공해야 한다. 개인 기록 저장은 개인 변경 이력을 만들지 않는다.
- 개인 기록·개인 첨부 파일의 변경 이력과 개인 내용을 담은 과거 값은 저장하지 않는다. 개인 상세에 이력 버튼·메뉴를 두지 않는다.
- 일반 편집으로 변경 이력을 수정하거나 지울 수 없다.
- 개인 기록·계정 삭제 시 공동 기록에 필요한 최소 삭제·연결 해제 사건만 남기고 개인 후기·완등·컨디션 등 개인 내용을 넣지 않는다. 계정 삭제 시 작업자 표시는 익명화한다.
- 살아 있는 기록의 수정 되돌리기는 과거 이력을 지우지 않고 새 변경으로 남긴다. 삭제된 공동 방문 기록의 복구는 제공하지 않는다.
- 공동 방문 기록 삭제는 관리자만 수행한다. 삭제 사건을 남기더라도 그 이력으로 공동 기록을 복구할 수는 없다. 각 회원의 개인 기록과 미디어는 삭제하지 않고 본인 개인 영역에 남긴다. 삭제 후 이력 보존 범위는 기능 명세에서 정한다.
- 두 사람이 동시에 수정했을 때 한 사람의 변경이 조용히 사라지지 않아야 한다. 충돌 알림 또는 항목별 병합 방식을 기능 명세에서 정한다.
- 접근·수정 권한은 화면뿐 아니라 서버에서도 확인한다.

## 11. 화면 구성 — 확정

### 하단 메뉴

하단 메뉴는 ‘일정 / 기록 / 암장 / 통계 / 내 정보’ 다섯 개로 구성한다. 암장 지도는 일정 작성과 독립적으로 이용한다. 상단 크루 이름 ⌄ → 선택창 → 크루 행 누르기로 바로 전환한다. 내 정보 → 내 크루 목록 → 크루 정보는 조회·관리 경로이며, 크루원 목록은 일정 화면의 ‘크루원’ 또는 내 정보에서 연다. 회원 목록 조회는 관리자 전용이 아니다.

| 메뉴 | 주요 내용 |
|---|---|
| 일정 | 달력·목록, 참여 중인 일정, 날짜 칸 → 해당 날짜 일정 조회·생성 |
| 기록 | ‘전체 / 내 방문 / 크루 방문’ 필터, 달력 날짜 칸 → 날짜 바텀시트 → 기록 조회·작성, 날짜·암장 필터. 크루 방문은 참석자 필터도 제공 |
| 암장 | 독립 암장 지도, 브랜드·지점·지역 검색, 지점 미리보기와 공통 암장 상세 |
| 통계 | 기간 선택, 방문 암장 수·방문 횟수·운동 일수, 주당 빈도, 난이도별 완등 개수, 컨디션 |
| 내 정보 | 프로필, 가입한 크루, 개인 보관함, 알림 설정·로그아웃. 회원·초대·관리는 가입 목록의 크루 정보에서 제공 |

일정 달력은 기록 달력과 같은 크기·표시 공간을 사용한다. 날짜를 누르면 해당 날짜의 전체 일정과 작성 동작을 담은 시트를 연다. 여러 건의 축약 표시와 공간 규칙은 [화면 설계의 공통 달력 규칙](./screen-design.md#231-표시와-공간-규칙)을 따른다.

### 상세 화면과 연결

| 화면 | 주요 내용과 동작 |
|---|---|
| 일정 상세 | 날짜·시간·암장, 참여·불참·미응답 명단, 참여·불참 선택, 권한에 따른 일정 수정·취소와 암장 변경. 연결 방문이 없으면 ‘방문 기록 만들기’, 있으면 ‘방문 기록 보기’ |
| 암장 선택·변경 | 한 화면에서 서버 등록 암장 검색과 현재 참여자 기준 추천 제공. 새로운 벽 평균·계산 인원·전체 벽 수 표시. 예정 세팅은 계산에만 반영하며 별도 표시 없음 |
| 크루 방문 상세 | 방문 날짜·암장, 실제 참석자, 공동 메모·공유 사진, 참석자별 공개 개인 기록 요약. 공동 정보 편집 및 관리자 삭제 |
| 내 기록 상세·편집 | 날짜·지점, 본인 완등 개수·컨디션·후기·사진·동영상, 연결된 크루 방문 표시 |
| 기존 기록 연결 | 같은 사람·날짜·암장의 기존 개인 기록 후보를 보여주고 본인이 연결할 기록 선택. 후보가 하나여도 확인 후 연결하며, 해당하는 기록이 없으면 새 개인 기록 작성으로 이동 |
| 다른 회원의 기록 | 크루원 목록 → 회원 선택 → 프로필·조회 가능한 전체 기록·통계(06.11) → 기록 상세(02.11). 크루 방문 참석자 선택은 해당 기록 상세로 바로 이동. 수치는 조회 가능한 기록에 표시하고 공개 미디어·후기는 현재 크루 방문에 연결된 기록에서만 표시 |
| 내 크루 목록 | 모든 크루 행은 >로 크루 정보 이동. 현재 상태는 이름 옆 표식. 크루 만들기·초대 가입 제공. 빠른 전환은 별도의 상단 선택창에서 수행 |
| 크루원 목록 | 조회 중인 크루의 회원 검색·목록·프로필, 회원별 기록·통계로 이동 |
| 사진·영상 보관함 | 내 정보에서 진입. 공동 방문 삭제 후 남은 업로더 본인 파일도 조회 |

### 기록 화면의 일관성

달력·목록·날짜 시트는 같은 필터와 방문 집계 기준을 사용한다. 연결된 개인 기록과 공동 방문을 중복 표시하지 않으며, 개인 상세는 진입 경로와 관계없이 같은 화면을 사용한다. 실제 참석과 개인 기록 유무는 구분한다.

대표 시각·기간 경계는 [기능 명세 S08](./functional-spec.md#s08-기록-목록--전체--내-방문--크루-방문), 배치와 화면 이동은 [화면 설계](./screen-design.md#screen-02-01), 연결·재연결은 [기록 관계 명세](./record-relationships.md)를 따른다.

### 관련 화면 안에서 여는 보조 화면

- 암장 상세: 벽 목록, 브랜드 난이도 체계, 세팅 이력·예정. 암장 선택 화면이나 일정·기록의 암장 정보에서 연다.
- 변경 이력: 일정·크루 방문에서만 연다. 조회·수정 권한을 지키며 개인 기록에는 이력 메뉴를 두지 않는다. 삭제된 크루 방문 복구는 제공하지 않는다.
- 회원 관리: 후순위 관리자 페이지에서 제공한다. 당장 크루 정보에 관리 메뉴를 구현하지 않는다.
- 브랜드·지점·벽·난이도·세팅 등록·갱신은 첫 버전 서비스 관리자 페이지에서 제공한다. 일반 회원용 모바일 데이터 편집 화면은 제공하지 않는다.

세부 배치·색상·컴포넌트 모양은 현재 제작한 Figma 시안과 최신 화면 설계를 따른다.

## 12. 첫 버전 완료 기준

1. 로그인·크루 생성·초대 가입·전환이 가능하고 크루별 접근 권한을 지킨다. 가입 크루가 없어도 개인 기록·통계·보관함을 이용한다.
2. 일정을 만들고 참여·불참으로 응답하며, 실제 참석은 별도 방문 기록에 저장한다.
3. 개인 기록 작성·수정과 크루 방문 연결을 제공하며 연결·해제로 기록과 통계를 복제하지 않는다.
4. 공동 정보 수정·이력·삭제와 개인 정보 소유권을 구분한다. 공동 방문 삭제 시 본인 기록·파일을 보존하고, 개인 변경 이력은 저장하지 않는다.
5. 파일 공개 범위·업로드 실패·삭제를 올바르게 처리하며 비공개 파일은 타인에게 노출하지 않는다.
6. 암장 지도·검색·벽별 세팅 추천과 서비스 관리자 데이터 등록·수정을 제공한다.
7. 기록한 개인 방문의 기간 통계를 제공하고 미입력 값을0으로 만들지 않는다.
8. 새 일정·일정 변경·취소·기록 요청 알림과 관리자 이관·탈퇴·계정 삭제를 확정 규칙대로 처리한다.

버튼·경계 상황·동시 요청까지 확인하는 상세 기준은 [기능 명세 9절의 완료 확인 시나리오](./functional-spec.md#9-기능-완료-확인-시나리오)를 따른다. 시안 검증은 실제 구현 완료를 뜻하지 않는다.

- 정기 모임 반복 생성
- 크루 전체의 회원 간 비교·순위와 운영 통계 화면. 개인별 기간 통계는 첫 버전에 포함한다.
- 이용권 구매·잔여 횟수 관리
- 암장 공지 자동 수집: 첫 버전은 수동 등록으로 확정

## 15. 개인 기간 통계

선택한 기간에 얼마나 자주 운동했고, 어디에 갔으며, 얼마나 완등했고, 컨디션이 어땠는지 보여준다. 본인이 저장한 개인 기록만 집계하고 공동 연결로 횟수를 늘리지 않는다. 계정 전체 개인 통계는 본인만 보며 회원 통계는 조회 가능한 기록만 집계한다.

방문 횟수와 운동 일수를 함께 보여주고, 방문 암장·주별 방문·난이도별 완등·컨디션 추이와 분포를 제공한다. 완등 합계는 입력된 개수이며 서로 다른 문제 수가 아니다. 컨디션은 선택 입력이며 건강 진단이나 성과의 원인으로 해석하지 않는다.

기간 종류·집계·미입력·빈 값 처리의 기준은 [기능 명세 S15](./functional-spec.md#s15-개인-통계)와 [5.3절](./functional-spec.md#53-통계-계산), 화면 배치·기간 선택창은 [04.01 화면 설계](./screen-design.md#screen-04-01)를 따른다.

## 16. 브랜드·지점·난이도 데이터

### 확정된 구조

- 암장 목록은 서버에 미리 등록한다. 사용자는 검색 결과에서 방문 지점을 선택한다.
- 브랜드마다 로고 이미지를 등록하고 각 지점은 연결된 브랜드 로고를 사용한다.
- 지점마다 표시 색상을 등록한다. 달력 방문 표시·기록 목록·암장 선택에서 같은 지점은 같은 색상을 사용한다. 브랜드 로고 원본은 임의로 변색하지 않는다.
- 지점 표시 색상과 완등 난이도 색상은 별개이며 서로 덮어쓰지 않는다.
- 브랜드에 난이도 목록을 등록한다. 난이도마다 고정된 숫자와 표시 이름·색상을 연결한다. 난이도 숫자 순서가 단계 순서다.
- 각 지점은 브랜드에 연결되며 해당 브랜드의 난이도 목록을 사용한다.
- 벽 목록과 세팅 이력은 브랜드 공통이 아니라 지점별로 관리한다.
- 지점별 벽 목록과 개수는 고정이다. 첫 버전의 운영 중 벽 추가·폐지·통합 기능은 범위에서 제외한다.
- 브랜드·지점·벽·난이도 데이터 등록용 서비스 관리자 페이지는 첫 버전에 포함한다. 운영자는 해당 페이지에서 암장·세팅 데이터를 등록·갱신한다. [관리자 명세](./admin-spec.md)를 따른다.

### 설계 시 지켜야 할 사항

- 방문 기록과 추천의 장소 단위는 지점이다. 같은 브랜드의 다른 지점을 방문해도 해당 지점의 방문 이력으로만 반영한다.
- 난이도는 브랜드 ID와 난이도 숫자로 구분한다. 색상 문자열은 기록의 식별자나 저장값으로 사용하지 않는다.
- 개인 기록의 완등은 브랜드 ID·난이도 숫자·개수로 저장한다. 색상은 브랜드별 난이도 숫자의 현재 매핑으로 표시한다. 색상 매핑을 바꿔도 저장한 난이도 숫자·개수는 바꾸지 않으며 과거 기록 편집과 통계도 같은 숫자를 사용한다(D05 확정).
- 모든 지점에는 브랜드가 반드시 연결된다. 같은 브랜드의 지점은 같은 난이도 숫자·색상 매핑을 사용한다. 브랜드 없는 암장과 지점별 별도 난이도 체계는 현재 범위에 없다.

## 17. 일정 장소 변경과 푸시 알림

### 장소 변경

- 일정 날짜·시간은 필수다. 암장은 미정으로 모집할 수 있다.
- 기존 권한대로 일정 작성자와 관리자가 암장을 변경한다. 당일이라는 이유로 변경을 막지 않는다.
- 암장 변경 화면은 추천 목록과 서버 등록 암장 검색을 함께 제공한다.
- 추천에는 현재 참여자 명단을 사용하며, 참여·불참 변경으로 명단이 달라지면 다시 계산한다.
- 과거 일정에서는 추천을 사용하지 않는다. 실제 방문 기록을 작성할 때의 암장 검색은 사용할 수 있다.
- 암장 변경은 일정 수정으로 처리한다. 참여·불참 응답은 별도 동작이며 암장 변경으로 초기화하지 않는다. 상세 동작은 [일정 수정·참여 응답](functional-spec.md#s04-일정-생성수정)을 따른다.
- 운동 후 실제 방문 기록과 예정 일정은 구분한다. 장소 변경이 이미 입력한 완등 등급·미디어·과거 방문을 조용히 다른 암장으로 옮기지 않도록 처리한다. 실제 방문 지점 정정은 B01에 따라 연결 중 변경을 막고, 본인이 연결 해제 후 정정·재연결한다.

### 확정된 푸시 종류

| 상황 | 목적 | 수신 대상 |
|---|---|---|
| 일정 생성 | 새 모임이 생겼음을 알리고 참여 신청 유도 | 작성자를 포함한 크루원 모두 |
| 암장 최초 지정·변경 | 방문 기록 유무와 관계없이 어디서 만날지 안내 | 해당 일정의 참여 신청자. 불참·미응답 제외. 변경한 본인도 참여자이면 수신 |
| 날짜·시간 변경 | 바뀐 약속을 안내 | 해당 일정 참여자 |
| 일정 취소 | 취소 사실 안내 | 취소 직전 해당 일정 참여자 |
| 일정 시간대의 당일 오후 9시까지 연결 방문 최초 생성 이력이 없는 경우 | 일정에 연결된 방문 기록 생성 유도 | 해당 일정 참여자. 오후 9시 이후 만든 일정은 제외 |

새 일정은 해당 크루의 크루원 모두에게, 오후 9시 기록 요청은 해당 일정 참여자에게 보낸다. 알림에 크루 이름을 표시하고, 다른 크루를 보고 있어도 해당 크루의 수신 조건에 맞으면 받는다. 알림을 열 때 소속 권한을 확인한 후 해당 크루의 일정으로 이동한다. 푸시를 누르면 해당 일정 또는 연결 방문 기록 생성 화면으로 이동한다. 푸시 수신 허용 여부를 존중한다. 기록 요청은 발송 직전에 취소 여부와 연결 방문 최초 생성 이력을 확인하고, 취소되지 않았으며 한 번도 생성한 적이 없을 때만 보낸다. 암장·날짜·시간 변경과 취소 알림에는 방문 기록 부재 조건을 적용하지 않는다. 기록 생성으로 일정이 종료 상태여도 허용된 변경이 저장되면 알림을 보낸다. 같은 사건·수신자 조합의 알림 사건·발송 작업을 중복 생성하지 않으며 서로 다른 변경은 별도 알림으로 처리한다. 외부 푸시 전달까지 정확히 한 번을 보장하지는 않는다. 변경 알림에는 이전·새 값을, 암장 최초 지정에는 정해진 장소를 표시한다.

기록 요청은 ‘연결 방문 기록을 한 번이라도 생성했는가’를 기준으로 한다. 생성 후 삭제한 경우에도 재요청하지 않는다. 기록이 있으면 완등 개수·컨디션·사진 등이 비어 있어도 보내지 않는다. 별도의 개인 미작성 독촉 알림은 넣지 않는다. 당일·일정 종료·오후 9시 알림은 일정에 저장한 시간대를 기준으로 판단한다. 알림 실행 시점은 UTC로 계산해 저장한다. 오후 9시 이후 생성된 당일 일정에는 기록 요청을 보내지 않는다. 이 조건은 이후 날짜의 일정을 전날 밤에 만들었다는 이유로 해당 일정 당일 알림까지 막는다는 뜻은 아니다. 오후 9시 이후 기존 일정 날짜를 당일로 바꾼 경우에도 보충 발송하지 않는다.

### 방문 기록 생성 또는 날짜 경과에 따른 종료 — 확정

- 일정의 수동 종료 버튼은 제공하지 않는다. 취소되지 않은 일정은 연결 방문 기록이 생성되거나 해당 날짜가 지나면 종료 상태로 취급한다.
- 날짜 경과로 종료돼도 실제 운동 여부·참석자가 확정되는 것은 아니며 방문 기록을 자동 생성하지 않는다.
- 크루원이 별도로 방문 기록을 만들고 일정에 연결한다. 당일에도 기록할 수 있고, 이때 일정이 종료로 취급된다. 연결되지 않은 개인 방문 생성은 다른 일정을 종료시키지 않는다.
- 종료 후에도 연결 방문 기록 생성과 권한에 따른 기록 수정은 가능하다. 일정 종료와 개인 운동 기록 입력 완료는 서로 다른 상태다.
- 방문 기록의 삭제 여부는 일정에 영향을 주지 않는다. 일정의 날짜·시간·암장·참여 신청·종료 상태를 바꾸거나 일정 자체를 삭제하지 않는다.
- 방문 기록 생성으로 한 번 종료된 일정은 해당 기록을 삭제해도 종료 상태를 유지한다. 종료를 단순히 ‘현재 연결 기록이 존재하는가’로 매번 다시 계산하지 않는다.
- 방문 기록 삭제 자체로 알림을 새로 보내거나 모임을 다시 모집하지 않는다. 이미 연결 방문을 생성했다면 삭제 후에도 오후 9시 기록 요청은 보내지 않는다(B04).
- 기록 요청 푸시는 자동 종료 시점에 보내는 것이 아니라, 일정에 저장한 시간대의 당일 오후 9시까지 연결 방문 최초 생성 이력이 없을 때 보낸다.
- 자동 종료 판단은 일정에 저장한 시간대를 사용한다. 실제 시점은 UTC로 저장하고 클라이언트는 기기 시간대로 표시한다. 일정·방문 모두 날짜·시간이 필수다.
- 개인 방문은 수동으로 사후 기록할 수 있다. 개인 운동 독려 푸시는 첫 버전에서 제외하며, 일정 종료를 위한 시작·종료 조작은 추가하지 않는다.
- 날짜·시간 변경과 취소 푸시도 첫 버전 확정 기능이며 일정 참여자에게 보낸다.

### 동시에 연결 기록을 만드는 경우 — 확정

- 먼저 같은 일정에 연결된 방문 기록이 있는지 보여주고 기존 기록을 열도록 안내한다.
- 단순히 화면에서 존재 여부를 검사하는 것만으로는 동시 생성을 막을 수 없다. 서버에서 중복 생성 검사와 저장을 한 번에 처리하는 방식을 사용한다.
- 같은 일정의 연결 공동 방문은 먼저 서버에 저장이 완료된 기록 하나를 사용한다. 화면을 먼저 연 사람이나 요청을 먼저 보낸 사람을 기준으로 하지 않는다.
- 서버에서 같은 일정의 중복 저장을 막고, 나중 생성 요청에는 먼저 저장된 기존 기록을 돌려준다. 요청 재시도에도 새 기록을 만들지 않는다.
- 자동으로 두 사람의 참석자 명단·메모를 합치거나 덮어쓰지 않는다. 저장하지 못한 입력은 보존하고 기존 기록에서 확인 후 반영하게 한다.
- 하나의 예정 일정에 연결해 보여주는 크루 방문 기록은 현재 남아 있는 기록 하나다. 같은 날짜에 방문 기록을 하나만 쓸 수 있다는 뜻은 아니다. 크루 방문을 삭제한 뒤에는 같은 날짜에 새 방문을 작성할 수 있고, 기존 일정에서도 새 크루 방문을 작성할 수 있다. 새 방문은 새 기록으로 저장하며 삭제된 방문을 복구하거나 보존된 개인 기록을 자동 연결하지 않는다. 개인 기록은 본인이 다시 선택해 연결한다. 일정 종료와 최초 방문 생성 사실은 유지하며 21시 기록 요청을 다시 보내지 않는다. 여러 장소 방문은 별도 방문 기록으로 남길 수 있으며, 하나의 일정에 여러 공동 방문을 연결하는 기능은 첫 버전 범위에서 제외한다. 개인 기록은 기존 기록 선택·연결 방식으로 해당 공동 방문에 붙인다.
