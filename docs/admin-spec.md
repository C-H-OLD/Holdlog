# Holdlog(가제) — 서비스 관리자 명세

## 1. 범위와 권한

서비스 관리자는 별도 웹에서 암장·브랜드·세팅 데이터를 등록·수정한다. 크루 관리자 권한과 구분하며, 크루 관리자라는 이유로 서비스 운영 데이터를 수정할 수 없다. 타인의 비공개 미디어나 개인 변경 이력 조회 기능은 제공하지 않는다.

앱 시작 공지의 이미지·링크·표시 순서도 관리한다. 앱 표시 동작은 [기능 명세 S26](./functional-spec.md#s26-앱-시작-공지-팝업)을 따른다.

A02·A03·A04는 관리자 웹 범위다. 모바일 크루 생성·이관은 [기능 명세 S24·S25](./functional-spec.md#s24-크루-만들기--첫-버전), 후순위 일반 회원 관리는 S18을 따른다. 최초 서비스 관리자 계정은 개발 환경 초기 설정에서 준비하며 공개 가입으로 권한을 부여하지 않는다.

## 2. 등록·수정 동작

| 화면 | 입력·동작 |
|---|---|
| A02 암장·브랜드 관리 | 브랜드: 이름·로고·난이도 이름·색상. 암장: 등록된 브랜드·지점 이름·시간대·주소·좌표·표시 색상·최초 벽 목록. 각각 새 항목 등록 또는 기존 항목 불러오기·수정 |
| A03 세팅 등록 | 지점·해당 지점의 벽·세팅 예정 날짜 입력. 기존 세팅 날짜 수정·취소 |
| A04 공지 관리 | 이미지·이동 링크·표시 순서 등록·수정. 기존 공지 삭제 및 확인창 |

### 브랜드·암장 저장과 입력 유지

- **브랜드 불러오기:** 새 항목은 ‘브랜드 등록’, 기존 항목은 현재 값을 채워 ‘브랜드 수정 저장’으로 저장한다.
- **암장 불러오기:** 새 지점은 ‘암장 등록’, 기존 지점은 현재 값을 채워 ‘암장 수정 저장’으로 저장한다. 암장 수정으로 브랜드 이름·로고·난이도를 덮어쓰지 않는다.
- 두 폼은 따로 저장한다. 저장 성공한 폼만 완료되며 다른 폼의 저장하지 않은 입력은 유지한다.
- 다른 항목을 불러오거나 화면을 나가면서 변경을 버리는 경우 ‘계속 작성 / 나가기’를 확인한다. 계속 작성은 입력을 유지한다. 나가기는 해당 변경만 버리며, 항목 전환 시 반대쪽 폼 입력은 유지한다. 실제 저장 중에는 해당 폼의 중복 실행을 막는다.

### 브랜드 난이도

난이도는 브랜드 추가·수정에서 이름·로고와 함께 저장한다. 암장 폼은 등록된 브랜드를 선택하며 난이도를 따로 입력·저장하지 않는다. 같은 브랜드의 지점은 같은 매핑을 사용한다.

‘난이도 추가’와 각 행의 삭제 버튼으로 개수를 바꾸며 이름·색상도 직접 수정한다. 개수는 고정하지 않고 임의의 최소·최대 제한을 두지 않는다.11색은 시안 예시다. 변경은 해당 브랜드 지점의 표시 정보에 반영하지만 과거 기록의 브랜드 ID·난이도 키·완등 개수와 통계는 보존한다. 항목 삭제로 과거 값이 사라지거나 다른 난이도로 바뀌어서는 안 된다.

### 벽 목록과 세팅

최초 벽 목록은 신규 암장 등록 때만 편집한다. 기존 암장 수정에서는 읽기 전용이며 벽 추가·폐지·통합은 현재 범위에서 제외한다.

세팅은 지점 현지 날짜와 확인 가능한 정밀도로 입력하며 알 수 없는 정확한 시각을 만들지 않는다. 지점의 기준 시간대는 IANA 식별자로 저장한다. 추천의 시간대·날짜 비교는 [기능 명세 5.4절](./functional-spec.md#54-암장-추천-계산)을 따른다.

세팅 수정은 같은 폼을 사용한다. 취소는 현재 화면 위 중앙 확인창에서 대상 암장·벽·날짜를 보여준다. 돌아가기는 변경 없이 닫고 세팅 취소는 해당 예정 세팅을 취소한다.

암장 대량 삭제·자동 공지 수집·반복 세팅 생성·일반 회원 관리 화면은 현재 범위에서 제외한다.

### 공지 관리

- 서비스 관리자만 공지 목록을 조회하고 각 이미지·이동 링크·표시 순서를 등록·수정하고 공지를 삭제한다. 일반 회원과 크루 관리자에게 관리 권한을 주지 않으며 서버에서도 변경 요청을 거절한다.
- 목록에서 기존 항목을 선택하면 같은 폼에 값을 채워 수정한다. 새 항목은 이미지·링크·순서를 입력해 등록한다. 저장한 내용은 다음 앱 시작의 공지 목록 조회에 반영한다.
- 기존 공지에는 ‘공지 삭제’를 표시하며 새 항목에는 표시하지 않는다. 누르면 현재 화면 위 중앙 확인창을 열고 취소는 공지를 유지한다. 삭제 확인 후 성공하면 목록과 이후 앱 공지 조회에서 제외한다. 삭제 실패는 공지를 유지하고 공통 다이얼로그로 처리한다. 서버는 삭제 권한도 확인하며 중복 실행을 막는다.
- 저장 전 입력을 변경해도 앱 조회 결과는 바뀌지 않는다. 저장 실패는 입력을 유지하고 공통 다이얼로그로 처리한다. 저장 중에는 중복 실행을 막으며 별도 상태 화면을 만들지 않는다.
- 관리자 저장·삭제가 사용자 기기의 당일 숨김 선택을 해제하지 않는다. 공지 조회·등록·수정·삭제 API 계약과 이미지 저장 방식은 설계에서 정한다.

## 3. 완료 확인 기준

- 삭제 성공한 공지는 목록·앱 조회에서 제외되고 취소·삭제 실패한 공지는 유지된다.
- 서비스 관리자 공지 저장 후 앱 조회의 이미지·링크·순서가 일치하며 권한 없는 변경 요청은 거절된다.
- 암장·세팅 등록 API는 서비스 관리자만 사용하며 일반 회원·크루 관리자 요청은 거절한다.
- 등록한 지점·난이도·벽이 모바일 기록 입력과 지도에서도 같은 정보로 보인다.
- 세팅 날짜 수정·취소가 추천 계산에 반영된다.
- 브랜드 변경 후 과거 기록의 난이도 키·완등 개수와 통계가 유지된다.
- 실패 시 입력을 유지하며 재요청으로 같은 자료를 중복 생성하지 않는다.

위 항목은 구현 후 확인할 기준이며 실행한 테스트 결과가 아니다. 배치·버튼·시안은 [관리자 웹 화면 설계](./screen-design.md#admin-web), 제작·검증 자료는 [Figma 현재 작업](./figma/README.md)을 따른다.
