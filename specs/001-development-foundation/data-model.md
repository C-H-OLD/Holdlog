# 개발 설정과 검증 자료

작성일: 2026-10-06 · 상태: 설계. 개발 자료의 논리 구조이며 제품 테이블은 정의하지 않는다. 업무 관계 원본은 [002 모델](../002-shared-contracts/data-model.md)이다.

## 개발 자료

| 자료 | 필요한 정보 | 관계·검사 |
|---|---|---|
| DevelopmentTarget | mobile/admin/api/worker, 경로, 도구 버전, 실행/검사 명령 | 같은 ContractBuild 사용, 실제 명령은 구현 후 확인 |
| EnvironmentConfig | development/test, API 주소, DB 연결, 파일 영역, 허용 Origin, worker 종류 | 개발/시험 분리. 운영 연결을 기본값으로 쓰지 않음 |
| SecretReference | 이름, 로컬 파일/환경 입력 위치, 소비 대상 | 비밀 원문을 공유 문서·검증 결과·앱 번들에 저장하지 않음 |
| ContractBuild | 계약 버전, 원본 SHA-256, 도구 버전, 출력 목록 | 원본 변경 시 재생성. 매번 달라지는 시각을 생성 결과에 넣지 않음 |
| VerificationRun | 커밋/작업 상태, 대상, FR/SC, 명령, 기대/실제 결과, 자료 종류, 기기 | 작성/통과/실패/미수행·mock/로컬/실기기/물리 서버 구분 |

## 공개 설정과 비밀 설정

| 대상 | 공개 예시 | 비밀·로컬 전용 |
|---|---|---|
| 모바일 | 개발 API origin·앱 식별자 예시 | 서명·네이티브 설정 파일. 공개 환경 변수에 서버 비밀을 넣지 않음 |
| 관리자 웹 | 상대 `/api/v1`·개발 proxy 대상 | DB 비밀번호·초기 관리자 비밀·서버 키는 웹 변수에 넣지 않음 |
| API | host/port·허용 Origin 예시·환경 이름 | DB 접속 값·서버 비밀·관리자 준비 입력 |
| worker | 작업 종류·기본 저장소 이름 | DB 접속 값·비공개 파일 경로·후속 발송 자격증명 |
| Compose | DB 주요 버전·서비스/개발 볼륨 이름 | 실제 DB 비밀번호·호스트 경로 |

필수 설정 누락은 설정 이름만 알려주고 실패한다. 값을 로그에 출력하지 않는다. 초기 계정/시험 자료는 합성 자료를 사용하고 운영 자료를 복사하지 않는다.

## 기반 DB와 작업

- DB 변경 적용 이력은 버전·checksum·적용 시각을 기록한다. 적용한 파일의 checksum 변경을 거절한다. 변경과 적용 기록은 가능한 같은 트랜잭션으로 처리하며 제품 테이블은 기능별 migration에서 추가한다.
- pg-boss 내부 자료는 라이브러리 스키마 관리에 맡긴다. 기반 합성 작업은 시험 jobId와 결과 표식만 사용하며 개인정보·파일 bytes를 넣지 않는다.
- 합성 작업 상태는 등록 → 처리 → 성공 또는 재시도 → 성공/실패다. worker 종료 후 재개·동일 jobId 효과 중복 방지를 검사한다. 실제 파일 변환·푸시 전달의 증거는 아니다.
- 관리자 principal/session은002 C02 원본을 참조한다.001은 비밀 전달·해시·교체 절차,004는 실제 저장·로그인/세션 구현과 검증을 맡는다.

## 상태 변화

설계 → 작업 준비 → 설치 → 로컬 실행 → 소비자 연결 → 실기기 확인의 증거를 따로 남긴다. 로컬 통과가 외부 검사 상태를 바꾸지 않는다. 설정 누락·DB 중지·네트워크 불가는 실패로 기록하고 재준비 뒤 같은 상황을 다시 검사한다. 제품 기능 완료는 각 스펙의 필수 결과를 충족한 뒤 판단한다.
